## Spacing Scale

Declared values (multiples of 4, matching Phase 19 import pages):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Compact element spacing, cell padding |
| md | 16px | Default element spacing, card content padding |
| lg | 24px | Section padding, tier headers |
| xl | 32px | Layout gaps between tiers |
| 2xl | 48px | Major section breaks, page-level gaps |
| 3xl | 64px | Page-level spacing (not used in import pages) |

Exceptions:
- Drop zone minimum height: 160px (established in Phase 19, carry forward)
- Touch targets for clickable table cells: minimum 44px height per row
- Tier section separator: 1px border + 24px vertical margin

Source: Phase 19 `app/(ops)/admin/import/[type]/page.tsx` patterns

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label / badge | 12px (text-xs) | 400 (regular) | 1.4 |
| Heading | 24px (text-2xl) | 700 (bold) | 1.2 |
| Section header / card entity label | 18px (text-lg) | 700 (bold) | 1.3 |

Notes:
- Column header cells in preview table: 12px, weight 700, uppercase, tracking-wider (established Phase 19 pattern)
- Result stat numbers: 24px, weight 700 (text-2xl font-bold) — matches Phase 19 commit result cards
- Status badge text: 12px (text-xs) — badge text merged into label size; no sub-12px text used in this phase
- All previously font-semibold (600) declarations are replaced with font-bold (700): section headers, card entity labels, recipe header rows in preview table

Max 4 sizes: 12, 14, 18, 24px. Max 2 weights: 400, 700.

Source: Phase 19 `[type]/page.tsx` className audit; revised per checker dimension 4 constraints

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | var(--background) — oklch(1 0 0) light / oklch(0.145 0 0) dark | Page background, table row backgrounds |
| Secondary (30%) | var(--card) / var(--muted) — oklch(1 0 0) / oklch(0.97 0 0) | Cards, tier group backgrounds, table header sticky row |
| Accent (10%) | var(--primary) — oklch(0.205 0 0) light / oklch(0.922 0 0) dark | Active drag-over border, primary CTA buttons, drop zone hover border |
| Destructive | var(--destructive) — oklch(0.577 0.245 27.325) | Invalid row cell bottom border, invalid badge, error text |

Accent reserved for:
- Drop zone border when `isDragOver === true`
- Drop zone border on hover (not default state)
- Primary import action buttons ("Parse File", "Import N Records")
- No other uses — all other interactive elements use muted/outline variants

Semantic state colors (carried forward from Phase 19):
- Valid row dot / result count: `bg-green-500` / `text-green-600`
- Invalid row dot / result count: `bg-red-500` / `text-red-600`
- Duplicate row dot / result count: `bg-amber-500` / `text-amber-600`
- Stock additive warning banner: `border-amber-300 bg-amber-50` (light) / `border-amber-800 bg-amber-950/20` (dark), text `text-amber-800 dark:text-amber-200`
- Stock re-import warning banner: same amber palette — "This file was already imported on {date}. Re-importing will create duplicate stock movements."
- Prerequisite missing warning on index cards: `text-amber-600` label + `AlertTriangle` icon (size-4)
- Blocked field error in commit: destructive toast via Sonner

Source: `globals.css` CSS variables, Phase 19 `[type]/page.tsx` semantic color classes

## Component Inventory

Components already installed — do NOT re-install:
`alert, badge, button, card, checkbox, combobox, dialog, dropdown-menu, input, label, popover, progress, scroll-area, select, separator, sheet, skeleton, sonner, switch, table, tabs, textarea, tooltip`

### Focal Point Declaration

- **Primary focal point on page load:** the upload drop zone. It is the largest interactive element on the page and receives the visual emphasis (prominent dashed border, centered icon + copy).
- **After parse:** the focal point shifts to the preview table and the "Import N Records" CTA. The table summary row count and the primary button are the most visually salient elements.

### Import Index Page (restructured — D-12)

**Tier section header:**
- `<p>` with `text-xs font-bold uppercase tracking-wider text-muted-foreground` + `<Separator />` below
- Spacing: `mt-8 mb-4` between tiers

**Import type card (with prerequisite state):**
- `<Card>` from shadcn with `<CardHeader>` + `<CardContent>`
- Icon: Lucide icon, `size-8 text-muted-foreground`
- Prerequisite warning: `<Badge variant="outline" className="text-amber-600 border-amber-300">` with `<AlertTriangle className="size-3 mr-1" />` and label text (e.g. "Needs: Missions")
- CTA: `<Button variant="outline" className="w-full">Import {label}</Button>`
- Cards with prerequisite warnings are still clickable — warning is informational, not a blocker on the card itself

**Prerequisite entity count pill (on index page — D-12):**
- Below page header: `<p className="text-xs text-muted-foreground">Loaded from GET /imports/prerequisites</p>`
- Display: "{N} ingredients · {N} vendors · {N} zones · {N} brands · {N} missions · {N} recipes (approved: N)"

### Import Type Page (extended)

**Stock additive amber banner (D-23):**
```
flex items-start gap-3 rounded-lg border border-amber-300 bg-amber-50 p-4
dark:border-amber-800 dark:bg-amber-950/20
```
- Icon: `<AlertTriangle className="size-4 text-amber-600 shrink-0 mt-0.5" />`
- Copy: "Stock imports are ADDITIVE. Each row adds to current inventory. If you import this file twice, quantities will be doubled."
- Always visible after a stock type is selected — not dismissible

**Stock re-import warning banner (D-09, D-22):**
- Same amber styling as above
- Displayed after parse if duplicate reference_id detected
- Copy: "This file was already imported on {date IST}. Re-importing will create duplicate stock movements. You may continue, but verify this is intentional."

**Recipe XLSX-only notice:**
- Displayed in Download Template section for `recipes` type
- `<Badge variant="outline">XLSX only</Badge>` next to template download button
- No CSV template button rendered for `recipes` type
- Copy below badge: "Recipes require two sheets (Recipe headers + BOM lines). CSV format is not supported."

**Recipe grouped preview table (D-14):**
- Recipe header row: `bg-[var(--muted)] font-bold` with full-width recipe name as leading cell; BOM lines count shown as badge
- BOM line rows: indented 24px in the first cell, `text-sm text-muted-foreground` for recipe_name column
- Expand/collapse toggle per recipe: `<ChevronDown>` / `<ChevronRight>` icon button at start of header row; `size-4`; `aria-label="Expand recipe {name}"` when collapsed, `aria-label="Collapse recipe {name}"` when expanded
- Recipe header row status badge uses same dot indicator pattern, but block icon if any BOM lines have errors

**Update Existing toggle — entity-specific label:**
- Shown for all types except `opening_stock` (which is always additive and shows amber banner instead)
- For `recipes`: "Replace BOM lines for matching draft recipes. Approved recipes are never modified."
- For `quests`: "Update matching quests. Quests with status other than 'planned' cannot be modified."
- For `tasks`: "Update matching tasks. Completed tasks (status = 'done') cannot be modified."
- For `events`: "Update matching events. Capacity cannot be reduced below existing bookings."
- For all others: default "Update existing records. Matching by name — existing records will be overwritten."

**Blocked field error display:**
- Inline in table: cell shows destructive bottom border (2px, `border-[var(--destructive)]`) + tooltip with exact reason
- Example tooltip: "Cannot change base_unit — stock records use g" or "Cannot modify approved recipe"
- Row badge: `<Badge variant="destructive" className="text-xs">Blocked</Badge>` (distinct from "Invalid")

**Row status dot legend:**
- Valid: `bg-green-500` dot
- Invalid: `bg-red-500` dot + "Invalid" badge
- Duplicate: `bg-amber-500` dot + "Duplicate — will update" or "Duplicate — will skip" badge
- Blocked: `bg-red-500` dot + "Blocked" badge (update attempt on protected field)

## Interaction States

### Upload Zone States

| State | Visual |
|---|---|
| Default (no file) | Dashed border `border-[var(--border)]`, `Upload` icon (size-12), muted foreground |
| Drag over | Dashed border `border-[var(--primary)]`, `bg-[var(--muted)]`, `scale-[1.01]` |
| File type error | Dashed border `border-[var(--destructive)]`, error text in `text-destructive` below icon |
| File selected | Solid border card with filename + filesize, X remove button (shows only if not yet parsed) |

### Parse States

| State | Visual |
|---|---|
| Pre-parse | "Parse File" primary button visible below file card |
| Parsing | `<Loader2 className="size-4 animate-spin" />` + "Parsing..." text + 5x `<Skeleton className="h-10 w-full" />` rows |
| Parse complete | Update Existing toggle + row count summary + preview table |

### Commit States

| State | Visual |
|---|---|
| Pre-commit | "Import N Records" primary button; disabled if importableCount === 0 |
| Committing | Button shows `<Loader2>` + "Importing..." text; disabled |
| Post-commit | Result cards (Imported / Updated / Skipped / Errors) replace commit button; amber error banner if errors > 0 |

### Table Row States

| State | Visual |
|---|---|
| Valid | Green dot, no badge, cells in default foreground |
| Invalid | Red dot, "Invalid" destructive badge, errored cell has `border-b-2 border-[var(--destructive)]` + `text-destructive` |
| Duplicate | Amber dot, "Duplicate — will update/skip" badge |
| Blocked | Red dot, "Blocked" destructive badge, blocked cell has bottom border + tooltip |
| Editing | `<Input className="h-7 text-sm" autoFocus />` replaces cell text; Enter to commit, Escape to cancel |

## Phase-Specific Constraints

### Stock Import (opening_stock type)
- No "Update existing" toggle is rendered. Replace toggle section with amber additive warning banner (always visible).
- Re-import detection: if parse response includes `warning: "duplicate_file"`, show a second amber banner above the preview table with the re-import message.
- Commit button label does not change from standard "Import N Records".

### Recipe Import (recipes type)
- Download Template section: render only `.xlsx` button (no `.csv` button).
- Add a `<Badge variant="outline">XLSX only</Badge>` next to the download button.
- Preview table: grouped display — recipe header row + collapsible BOM line rows beneath.
- Recipe header row background: `bg-[var(--muted)]` with `font-bold`.
- BOM line rows: `pl-6` indentation on status column cell; `text-muted-foreground` for recipe_name column.
- Expand/collapse: `<button>` with `<ChevronDown>` / `<ChevronRight>` icon; all recipes default to expanded; `aria-label="Expand recipe {name}"` when collapsed, `aria-label="Collapse recipe {name}"` when expanded.
- Per-recipe "block" state: if recipe header is invalid, all BOM rows show as `opacity-50 pointer-events-none`.
- Add static info banner: "Recipes import as drafts. Approve them in the app before linking to menu items." (info blue styling: `border-blue-300 bg-blue-50 dark:border-blue-800 dark:bg-blue-950/20`, `text-blue-800 dark:text-blue-200`, `<Info className="size-4 text-blue-600" />`).

### Import Index Page Restructure (D-12)
- Replace flat `grid-cols-3` with tiered section layout.
- Prerequisite check: call `GET /imports/prerequisites` on page load; display live entity counts in subtitle below page heading.
- Cards with missing prerequisites show amber warning badge but remain clickable.
- Dependency arrows: do NOT add visual arrows between tiers — the tier section headers and badge warnings are sufficient.
- Layout: each tier uses `<div className="space-y-3">` internally with `grid grid-cols-1 md:grid-cols-4 gap-4`.
