| Accent (10%) | `--primary` | oklch(0.922 0 0) ≈ #eaeaea | oklch(0.205 0 0) ≈ #252525 | Reserved for specific elements only (see below) |

- Sidebar active nav item (Operations section)

**Semantic colors (non-destructive):**
- Food cost % green: `text-green-500` — food cost < 30%

- Food cost % red: `text-red-500` / `text-destructive` — food cost > 40%

## Page & Layout Contracts

### /operations/recipes

**Layout:** Full-width content area. Header row: page title ("Recipes") + "Create Recipe" ShimmerButton. Filter row: Brand Select + Status Select + search Input. Content: responsive card grid (3 cols desktop, 2 tablet, 1 mobile). Each card is RecipeCard.

**RecipeCard anatomy:**
- Row 1: Recipe name (heading, 16px semibold) + RecipeStatusBadge
- Row 2: Brand badge (outline) + Zone badge (outline) + yield display (e.g. "10 portions")
- Row 3: Computed cost (if available) with `₹` prefix + NumberTicker; food cost % if linked to menu item
- Row 4: Edit button (InteractiveHoverButton) + Archive button (destructive icon, admin-only)
- MagicCard wrapper with gradientColor `#1a1a2e`
- ShineBorder (3s) on newly created recipes

**Click on card:** Navigate to `/operations/recipes/[id]` (recipe detail page).

### /operations/recipes/[id]

**Layout:** Two-column (2/3 + 1/3 on desktop, stacked on mobile).
- Left col: Recipe details (name, description, steps, cooking method, yield, portion size, shelf life, brand, zone, image). Edit triggers wizard from step 1 pre-filled.
- Right col: BOM section (RecipeDependencyTree) + computed cost breakdown.

**Dependency tree:** Nested indented list. Each level indented 16px. Each node: icon (Lucide `Leaf` for ingredient, `ChefHat` for sub-recipe) + name + qty + unit. Clicking a sub-recipe node navigates to that recipe's detail page. Max visual depth displayed: unlimited (scroll if deep).

**Computed cost panel:** Shows total `computed_cost` with NumberTicker. Below: line-by-line breakdown (ingredient name, qty × price = subtotal). If no vendor prices, show error state copy.

### Recipe Wizard (Sheet, full-height)

**Step indicator:** 3 numbered circles at top of sheet. Active = accent fill + white number. Completed = checkmark. Upcoming = muted outline. Step labels below circles: "Details", "Ingredients", "Review".

**Step 1 — Recipe Details:**
Fields (all in a single scrollable column):
- Name (Input, required)
- Description (Textarea, 3 rows)
- Prep Steps (Textarea, 5 rows, placeholder: "1. Marinate chicken for 2 hours\n2. Heat pan to medium-high...")
- Cooking Method (Input)
- Yield Qty (Input, number) + Yield Unit (Select: g, ml, pieces, portions)
- Portion Size (Input, display-only text e.g. "200ml")
- Shelf Life Hours (Input, number, optional, placeholder: "48")
- Brand (Select from brand list)
- Zone (Select from zone list)
- Image Upload (single file, same presigned URL pattern as assets)
- Status (Select: draft/approved/archived, shown only in edit mode)

CTA: "Next: Add Ingredients" (Button primary, disabled until Name + Yield filled)

**Step 2 — BOM Lines:**
Header: "Add the ingredients and sub-recipes this dish requires."
BOM line table with columns: Type | Item | Quantity | Unit | Prep Notes | Remove
- Type: Select ("Raw Ingredient" / "Sub-Recipe")
- Item: Combobox — when type=ingredient shows ingredient list, when type=recipe shows recipe list. Uses p-combobox-3 pattern. Placeholder: "Search ingredients..." / "Search recipes..."
- Quantity: Input (number, min 0.001)
- Unit: Select (units compatible with selected item's base_unit, or any unit if recipe type)
- Prep Notes: Input (optional, placeholder: "trimmed and diced")
- Remove: Trash icon button (destructive hover)

"Add Line" button below table (outline style, full width). Minimum touch target 44px height.

CTA: "Next: Review & Cost" (primary, enabled even with 0 lines — warn but don't block)

**Step 3 — Review & Cost:**
Read-only summary of all step 1 fields. BOM line summary table (read-only). Computed cost card: animated NumberTicker showing `₹[amount]` with "per batch" label. If cost cannot be computed, show error copy inline. Back buttons available on steps 2 and 3.

CTA: "Publish Recipe" (ShimmerButton, creates and saves)

### /operations/ingredients

**Layout:** Full-width. Header: "Ingredients" title + "Add Ingredient" button. Filter row: category Tabs (All | Dairy | Vegetable | Spice | Grain | Meat | Oil) + search Input. Content: Table (IngredientRow per row).

**Table columns:** Name | Category | Base Unit | Min Stock Level | Actions (Edit pencil)
- Category: colored Badge (each category gets a consistent muted color — no semantic meaning, just visual differentiation)
- Base Unit: monospace font (Geist Mono, 12px)
- Min Stock: number + base_unit abbreviation (e.g. "500 g")
- Actions: edit icon (Pencil from lucide), admin-only delete icon (Trash2, destructive)

**Ingredient form (Sheet):** Name, Category (Select), Base Unit (Select: g, ml, pieces, kg, L), Min Stock Level (Input + unit label). No unit conversion UI — system manages conversions automatically.

### /operations/vendors

**Layout:** Full-width. Header: "Vendors" title + "Add Vendor" button. Content: Table with columns: Name | Phone | Email | Payment Terms | Status | Actions.
- Status: VendorStatusBadge (active green, inactive muted)
- Actions: View detail (Eye icon) + edit (admin) + deactivate toggle (admin)

**Vendor detail:** Click row or Eye icon opens a Sheet panel (not a separate page). Shows: vendor info at top, then "Linked Ingredients & Prices" section. Section contains ingredient rows, each expandable to show price history (sorted effective_date DESC). Current price row highlighted with accent border-left. "Add Price" button per ingredient row opens VendorPriceForm sub-sheet.

**VendorPriceForm:** Ingredient (Combobox search), Price per base unit (Input with ₹ prefix), Effective Date (date Input), optional Notes. Submit saves VendorPrice record.

### /operations/menu

**Layout:** Full-width. Header: "Menu" title + "Add Menu Item" button (visible per-brand). Brand selector: Tabs at top (one tab per brand with active food brands). Active tab shows brand's categories.

**Per-brand layout:** Category sections (collapsible, default expanded). Each category has: section header (category name + item count + "Add Item" button + collapse chevron). Within each section: responsive card grid (MenuItemCard).

**MenuItemCard anatomy:**
- Row 1: Item name (heading 16px semibold)
- Row 2: Base price (₹ format, 14px) + FoodCostBadge (color-coded %)
- Row 3: Availability toggle (Switch, inline label "Available") — immediate save on toggle
- Row 4: "Edit" InteractiveHoverButton + "Remove" destructive icon (admin only)

**Channel Modifiers section:** Below the category sections, a collapsible "Channel Pricing" section. Contains ChannelModifierTable with columns: Channel | Modifier Type | Value | Effective Price | Edit. Inline editing: click Edit → row turns editable with Save/Cancel. Each row shows computed effective price (base_price ± modifier) in muted text.

**Add/Edit Menu Item (Sheet):**
Fields: Recipe (Combobox, approved recipes only), Category (Select), Base Price (Input, ₹ prefix), Image URL (optional Input). Food cost % auto-calculated from recipe computed_cost / base_price and displayed read-only below price field with color coding. Availability (Switch, default on).

## Interaction Patterns

### Wizard Navigation
- Progress through steps via "Next" buttons only (no clickable step indicators to jump ahead)
- Back buttons on steps 2 and 3 preserve entered data (controlled form state in parent)
- Step 1 validation: Name and Yield Qty required before advancing. Visual: required fields show `*` and inline error on blur.
- Closing the wizard mid-flow triggers unsaved-changes Dialog: "Discard changes?" / "Keep editing"

### BOM Line Management
- New line added at bottom with blank type. Type Select opens first — item Combobox disabled until type selected.
- Drag-to-reorder: not in v1. Sort order managed by add order (sort_order increments).
- Removing a line is instant (no confirmation — low stakes, within wizard).
- Combobox search: debounced 300ms. Minimum 1 character to trigger search.

### Food Cost % — Live Calculation
- On menu item form, food cost % recalculates client-side whenever base_price field changes.
- Formula: `(recipe.computed_cost / base_price) * 100`
- Color updates live as user types price.
- If recipe has no computed_cost, show "Cost not available" in muted text instead.

### Availability Toggle (Menu Items)
- Toggle is immediate — PATCH /menu-items/:id with { available: true/false } fires on change.
- Loading state: toggle shows spinner icon for 500ms.
- Success: Sonner toast "Item marked as unavailable" / "Item marked as available".
- Error: toggle reverts, Sonner toast "Failed to update availability. Try again."

### Computed Cost Display
- NumberTicker animates cost from previous value to new value on recalculation.
- Recalculation triggered: on recipe save, on vendor price save.
- If cost is null (no vendor prices), display "—" in muted text with tooltip "Add vendor prices to calculate cost".

### Dependency Tree Navigation
- Each sub-recipe node in the tree is a clickable link (underline on hover, cursor pointer).
- Click navigates to `/operations/recipes/[id]` of the referenced recipe.
- Ingredients (leaf nodes) are not clickable.
- Tree renders on recipe detail page only (not on wizard step 3 — step 3 shows BOM table only).

### Status Workflow
- Recipe status changes via Edit button (wizard pre-filled, status field visible in edit mode only).
- Status transitions: draft → approved, approved → archived, draft → archived.
- "Archive" action shortcut on RecipeCard directly triggers Dialog (no need to open wizard).
- Approved recipes cannot revert to draft (enforced server-side; UI hides draft option in edit if currently approved).
