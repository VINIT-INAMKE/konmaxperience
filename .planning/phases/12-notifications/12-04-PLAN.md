**Page component structure:**

State:
- `activeTab`: string — 'all' | 'unread' | 'tasks' | 'approvals' | 'ops'
- `loadedItems`: Notification[] — accumulated items for "load more" pattern
- `cursor`: string | null — last notification ID for keyset pagination
- `hasMore`: boolean — whether more items exist

Tab filter mapping (converts tab to API query params):
```typescript
const TAB_FILTERS: Record<string, string> = {
  all: '',
  unread: 'is_read=false',
  tasks: 'type=task_due,task_blocked',
  approvals: 'type=approval_pending',
  ops: 'type=low_stock,new_order,order_ready,delivery_update',
};
```

Data fetching:
- Use `useQuery` with `queryKey: ['notifications', 'page', activeTab, cursor]`
- Query path: `/notifications?limit=20${cursor ? '&cursor=' + cursor : ''}&${TAB_FILTERS[activeTab]}`
- When tab changes, reset `loadedItems` to [] and `cursor` to null
- On successful fetch, append new items to `loadedItems`. If returned count < 20, set `hasMore = false`.

Mark all read mutation (same pattern as NotificationBell):

**1. Add order-ready Sonner toast to NotificationBell:**

Per UI-SPEC interaction contract: "Order ready notification (NOTF-06) shows a Sonner toast with `sonner.success("Order #${id} is ready")` because POS staff may be looking at a different page. Duration: 5000ms."

In `NotificationBell.tsx`, add a `useEffect` that detects when unread count increases and the latest notification is of type `order_ready`. Implementation:

```typescript
import { toast } from 'sonner';
import { useRef } from 'react';

// Inside NotificationBell component:
const prevUnreadRef = useRef<number>(0);

// After unreadData is fetched:
useEffect(() => {
  if (unreadCount > prevUnreadRef.current && unreadCount > 0) {
    // Unread count increased — check if latest is order_ready
    // Fetch the single most recent notification to check type
    apiClient
      .get<Notification[]>('/notifications?limit=1')
      .then((items) => {
        if (items[0]?.type === 'order_ready' && !items[0].is_read) {
          const shortId = items[0].reference_id?.slice(-6).toUpperCase() ?? '';
          toast.success(`Order #${shortId} is ready`, { duration: 5000 });
        }
      })
      .catch(() => {}); // silent failure
  }
  prevUnreadRef.current = unreadCount;
}, [unreadCount]);
```

This fires only when unread count increases (not on initial mount — prevUnreadRef starts at 0 but the first render sets it without showing toast because the condition `unreadCount > prevUnreadRef.current` is still met; to prevent initial flood, initialize prevUnreadRef inside a useEffect that runs once to seed it):

```typescript
const [seeded, setSeeded] = useState(false);
useEffect(() => {
  if (!seeded && unreadCount >= 0) {
    prevUnreadRef.current = unreadCount;
    setSeeded(true);
  }
}, [unreadCount, seeded]);
```

Then the main effect only runs when seeded is true:
```typescript
useEffect(() => {
  if (!seeded) return;
  if (unreadCount > prevUnreadRef.current && unreadCount > 0) {
    // ... toast logic
  }
  prevUnreadRef.current = unreadCount;
}, [unreadCount, seeded]);
```

**IMPORTANT:** Per UI-SPEC: "On new notification arriving during polling (unread count increases): do NOT show a Sonner toast — bell badge update is sufficient. Exception: Order ready notification (NOTF-06) shows a Sonner toast." The logic ONLY toasts for `order_ready` type, not for all new notifications.
