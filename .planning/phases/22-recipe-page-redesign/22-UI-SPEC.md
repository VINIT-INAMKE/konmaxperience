## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline cell padding, badge padding |
| sm | 8px | Gap between header metadata fields, BOM column gaps |
| md | 16px | Default element spacing, card padding, section gaps |
| lg | 24px | Major section separation (header → BOM table, BOM table → instructions) |
| xl | 32px | Page horizontal padding, layout column gap |
| 2xl | 48px | Sticky cost panel top offset from header |
| 3xl | 64px | Page-level top padding |

Exceptions:
- BOM table row height: 44px minimum (touch target, Tab-navigable row)
- Drag handle column width: 32px fixed (GripVertical icon touch area)
- Status banner height: 48px fixed (prominent enough to signal workflow state)
- Sticky cost panel top: `top-[var(--header-height, 64px)]` to clear the ops nav

Source: standard 8-point scale; exceptions from D-05, D-12 (CONTEXT.md)

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 400 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display (recipe name editable field) | 28px | 700 | 1.15 |

Notes:
- Body (14px / 400) used for BOM table cell text, metadata field values, cost panel line items
- Label (12px / 400) used for column headers, field labels above metadata inputs, muted helpers
- Heading (20px / 600) used for section headings ("Bill of Materials", "Instructions", cost panel title)
- Display (28px / 700) used ONLY for the inline-editable recipe name field at the top of the page — document-editing feel per D-03

Source: matches existing RecipeCard pattern (text-base/font-semibold = 16/600, text-xs = 12); display size aligns with h1 in current detail page (text-2xl/font-bold); reduced to 28px for editable field aesthetics.

## Color

All values use CSS variable tokens with `var()` wrapper per project convention.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `oklch(1 0 0)` | Page background, editable field backgrounds |
| Secondary (30%) | `var(--card)` / `oklch(1 0 0)` light; `var(--muted)` / `oklch(0.97 0 0)` | BOM table rows (alternating), sticky cost panel card, metadata field group background |
| Accent (10%) | `var(--primary)` / `oklch(0.205 0 0)` | Reserved elements only (see below) |
| Destructive | `var(--destructive)` / `oklch(0.577 0.245 27.325)` | Archive button, remove BOM line button hover state |

Accent (`var(--primary)`) reserved for:
1. Save button (primary filled CTA)
2. "Submit for Approval" button in the draft status banner
3. "Approve" button in the pending status banner (approver-only)
4. Drag handle active/grabbed state
5. Estimated cost value during client-side calculation (before server confirmation)

Status banner colors (semantic, not accent):
- Draft banner: `bg-[var(--muted)]` with `text-[var(--muted-foreground)]` — neutral/subdued
- Pending banner: `bg-amber-500/10` with `text-amber-600 dark:text-amber-400` — amber/warning
- Approved banner: `bg-[var(--success)]/10` with `text-green-600 dark:text-green-400` — green/confirmed
- Archived banner: `bg-[var(--muted)]/50` with `text-[var(--muted-foreground)] line-through` — muted/struck

Cost panel semantic colors:
- Estimated badge: `bg-amber-500/10 text-amber-600` — signals server not yet confirmed (D-09)
- Missing price warning: `text-amber-500` with `WarningIcon` — partial cost state (D-10)
- Confirmed cost value: `text-[var(--foreground)]` at Display weight — authoritative

Source: globals.css tokens; CONTEXT.md D-09, D-10, D-12; existing RecipeStatusBadge pattern extended

## Layout Contract

### Page-level grid (D-01)

```
[ Page container: max-w-7xl mx-auto px-8 py-8 ]
  [ Page header: recipe name (editable) + unsaved dot + Save button ]
  [ Status banner: full-width, 48px, status-colored ]
  [ Two-column grid: grid-cols-[1fr_320px] gap-8 ]
    [ Left column (main, ~70%): metadata grid + BOM table + instructions ]
    [ Right column (sticky, ~30%, top-64px): cost panel ]
```

### Two-column sticky pattern

- Left column scrolls normally
- Right column: `sticky top-[64px] self-start` — stays visible as left scrolls
- Cost panel max height: `max-h-[calc(100vh-96px)] overflow-y-auto`

### BOM table column layout

```
[ 32px drag handle ] [ type select: 110px ] [ item combobox: 1fr ] [ qty: 80px ] [ unit: 90px ] [ prep notes: 160px ] [ cost: 80px ] [ remove: 32px ]
```

Tab order: type → item → qty → unit → prep notes → (next row type)

## Interaction Contracts

### Inline editing (D-03)

- Recipe name field: renders as plain text at rest; `contentEditable` div or `Input` with `border-transparent focus:border-input` transition — 0 visual border at rest, standard border on focus
- Metadata grid fields: same pattern — label above, value as styled input with transparent border at rest
- No "Edit mode" toggle — every field is always editable on draft/pending recipes
- Approved recipe: all fields render as static text (not inputs), `pointer-events-none`, reads as a document

### Unsaved changes indicator (D-04)

- Amber dot (`size-2 rounded-full bg-amber-500`) + "Unsaved changes" text (12px / muted-foreground) in page header next to Save button
- Both appear only when `isDirty === true`
- `beforeunload` event listener registered when `isDirty === true`, removed on clean save
- No custom discard modal — browser native dialog handles navigation guard

### BOM table drag-and-drop (D-05)

- Library: `@dnd-kit/core` + `@dnd-kit/sortable` (new dependency)
- GripVertical icon (Lucide) in leftmost column of each row
- Cursor: `grab` at rest, `grabbing` while dragging
- Dragged row: `opacity-50` on original, ghost shows at drop target
- Reorder updates `sort_order` in local state immediately; persisted on Save

### BOM empty row + Add Line (D-07)

- A persistent empty ghost row always exists at the bottom of the BOM table
- Clicking into the type select on the ghost row activates it and creates a real row
- "+ Add Line" button below the table (Button variant="outline" size="sm") for explicit discoverability
- Removing the last row: ghost row remains, table never has 0 rows in UI

### Sub-recipe inline expansion (D-08)

- ChevronRight icon on rows where `input_type === 'recipe'`
- Click toggles expansion — ChevronDown when open
- Expanded: `RecipeDependencyTree` renders below the row, `pl-8` indent, `bg-muted/30` background
- Read-only — cannot edit sub-recipe ingredients from parent's BOM

### Live cost calculation (D-09)

- Client-side: recalculates on every qty/item change using pre-fetched vendor prices + sub-recipe `computed_cost`
- Server-side: 3-second debounce after last edit — POST to cost preview endpoint
- While client estimate is displayed: `CostEstimateBadge` shows "estimated" in amber
- On server response: badge switches to "confirmed" in green, `NumberTicker` animates to authoritative value
- Lines with no vendor price: show `—` in cost column with `text-amber-500`

### Status banner actions (D-12)

- Draft: `[Submit for Approval]` — primary button; triggers PATCH status → `pending`
- Pending (approver only): `[Approve]` primary + `[Reject]` outline destructive — both in banner
- Approved: `[Create New Version]` outline + `[Archive]` ghost destructive
- Non-approver viewing pending: banner shows status only, no action buttons
- All transitions: optimistic UI update with `toast.success` on confirm

### Approved recipe lock (D-14)

- All fields render as static display text, no inputs
- Status banner shows "Approved — locked for editing" text
- "Create New Version" button: confirm dialog → POST clone endpoint → navigate to new draft

## Loading & Skeleton Contract

Page loading state (before recipe data arrives):
- Full page skeleton: recipe name area (h-10 w-64), metadata grid (4 × h-8 rows), BOM table (3 × h-11 rows), cost panel (3 × h-8 blocks)
- Use `Skeleton` component with same layout structure as loaded state — no spinner or "Loading..." text

BOM row loading (item search):
- Combobox shows spinner icon in the input while fetching ingredient/recipe list

Cost recalculation:
- `NumberTicker` animates smoothly; `CostEstimateBadge` appears instantly on first edit — no spinner
