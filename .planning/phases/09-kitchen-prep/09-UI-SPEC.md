## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, badge padding |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, wizard step gaps |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- KDS touch targets: minimum 48px height on all tappable order item rows (kitchen tablet)
- KDS order card minimum width: 280px (readable at distance on kitchen monitor)
- Wizard step indicator: 32px × 32px step circles
- Elapsed timer display: minimum 40px height (large legible numbers)

Source: D-05 (large touch targets, kitchen monitor), project-wide 8-point scale

## Interaction Contract

### Prep Batch Wizard — Step 2 Deduction Review

- Each BOM input row shows: input name | current available qty | required qty | status
- When available < required: row background `destructive/10`, text `text-destructive`, "Insufficient" badge
- "Start Batch" (Step 3 confirm) button is `disabled` when ANY input is insufficient
- Disabled confirm button shows tooltip: "Insufficient stock for one or more inputs"

Source: D-01

### KDS — Item Status Advancement

- Tap / click KdsOrderItem row to cycle: `pending` → `preparing` → `ready`
- On status change: Sonner toast (bottom-right): "{item name} marked {new status}"
- When ALL items in an order reach `ready`: order card background briefly flashes green (200ms), then starts 30s fade-out countdown
- 30s after all-ready: order card fades to opacity-0 over 1s transition, then removed from DOM

Source: D-06, D-10

### KDS — New Order Appearance

- New order card enters with BorderBeam animation overlay (duration 3s)
- After 3s BorderBeam animation completes: remove animation, card returns to standard styling
- No sound. No other notification.

Source: D-08

### KDS — Polling

- React Query `refetchInterval: 5000` (5 seconds)
- No loading spinner on background polls — silent refresh
- On poll error (network issue): show small fixed banner at top: "Connection issue — retrying..."

Source: D-09

### Prep Batch Expiry Display

- `expires_at` relative display in ExpiresInCountdown:
  - > 4 hours: neutral text, e.g. "6h 12m"
  - 1–4 hours: amber text `text-amber-600`, e.g. "2h 45m"
  - < 1 hour: red text `text-destructive`, e.g. "0h 32m"
  - Expired: static "Expired" badge (PrepBatchStatusBadge status=expired)

Source: D-02, D-13

### Menu Availability Display

- When servings remaining > 0: "X servings left" in `text-muted-foreground` (14px)
- When servings remaining === 0: "Sold Out" in `text-destructive font-semibold`
- Availability endpoint called on POS item grid (Phase 10) — no UI component in Phase 9 beyond the availability calculation endpoint

Source: D-11

## KDS Full-Screen Layout Contract

The KDS is the only page in the system that hides the sidebar. Implementation approach:

- Route: `/operations/kitchen/kds` as a **separate layout segment** that overrides the ops layout to hide sidebar
- OR: CSS-based approach — `position: fixed; inset: 0; z-index: 50` on KDS container, renders over sidebar
- The Exit button (`KdsExitButton`) positioned `fixed top-4 right-4` returns to `/operations/kitchen/kds` standard view or navigates back
- Toggle mechanism: URL-based full-screen mode via query param `?fullscreen=true` is simpler than CSS fullscreen API — avoids browser permission issues on tablets

Source: D-05 (Claude's Discretion — implementation approach), D-03 (sidebar structure)
