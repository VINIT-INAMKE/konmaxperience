## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact field spacing, chip gaps |
| md | 16px | Default card content padding, form field gaps |
| lg | 24px | Section padding, card-to-card gutters |
| xl | 32px | Page header to content gap |
| 2xl | 48px | Major section breaks (Pick & Pack page top) |
| 3xl | 64px | Page-level vertical spacing |

Exceptions:
- KDS-style touch targets (order item rows): minimum height 48px — matches existing `KdsOrderItem` min-h-[48px] pattern
- Preparation type selector buttons: minimum height 44px for reliable touch targeting on kitchen displays

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` — oklch(1 0 0) light / oklch(0.145 0 0) dark | Page backgrounds, form areas, table rows |

- Active border on focused form field (`focus:border-[var(--primary)]` — existing RecipeMetaGrid pattern)

- Preparation type selector: active/selected segment highlight

Semantic colors (additional, established in globals.css):
- `var(--success)` — oklch(0.59 0.2 145): "Available" availability badge, "All Items Ready" order status, batch item checked state
- `var(--info)` — oklch(0.55 0.18 250): "Batch Prepared" preparation type badge, informational availability counts
- Amber (`text-amber-400`): item notes in Pick & Pack cards — matches existing KdsOrderItem pattern for notes
- `var(--muted-foreground)`: secondary text on history rows, timestamps, zone names

## Screen-by-Screen Interaction Contract

### 1. Recipe Builder — preparation_type Selector (RecipeMetaGrid)

**Location:** Inline in RecipeMetaGrid, inserted as the first field before Brand, using full-width row above the existing 4-column grid.

**Component:** RadioGroup (horizontal button group) or 4-option segmented control built from styled RadioGroupItem buttons.

**Layout:** 4 options in a single horizontal row, full width. Each option shows:
- Icon: UtensilsCrossed (scratch), Package (batch_prepared), ShoppingBag (ready_to_sell), Layers (assemble)
- Label: "Fresh Prep" / "Ready to Sell" / "Batch Prepared" / "Assembly"
- 12px muted subtext: "Made per order" / "Off the shelf" / "Pre-batched" / "Combine parts"

**Visual states:**
- Unselected: `border border-border bg-transparent text-muted-foreground`
- Selected: `border border-primary bg-primary/5 text-foreground font-medium`
- Disabled (approved recipe locked): `opacity-50 pointer-events-none`

**Behavior:** Selecting `ready_to_sell` shows an amber info note below: "Prep steps and cooking method are optional for shelf items."

**Touch target:** Each option button minimum height 44px.

---

### 2. Ingredient Form — usage_type Selector

**Location:** First field in IngredientForm Sheet, before name. Three options as a segmented toggle.

**Component:** Three RadioGroupItem buttons in a row.

**Options:** "Recipe Ingredient" (Wheat icon) / "Disposable Supply" (Package icon) / "Reusable Equipment" (Wrench icon)

**Visual states:** Same pattern as preparation_type selector above.

**Behavior:** Selecting `supply` or `equipment` shows an amber info note: "This item will not appear in recipe BOM lines."

---

### 3. Ingredient Form — Category Dropdown

**Location:** Existing category field. Replace hardcoded INGREDIENT_CATEGORIES array with DB-driven Select.

**Component:** Existing `Select` component — no change to visual pattern.

**Data source:** `GET /ingredient-categories` — same fetch pattern as zones/brands in other forms.

**Loading state:** Skeleton in SelectTrigger while loading.

---

### 4. Pick & Pack Page (`/operations/kitchen/pick-and-pack`)

**Layout:** Full-page ops layout. Single-column queue of order cards. No sidebar split (unlike waste/supply usage which has two-column). Orders sorted by created_at ascending (oldest first).

**Empty state:** Centered icon (PackageCheck) + heading "Nothing to pack" + body "Non-scratch order items will appear here when orders come in."

**Order cards:**

Each card is a white Card with:
- Header row: Order number as Display (28px bold), customer name in 14px muted, elapsed timer (reuse KdsElapsedTimer), channel badge (Takeaway / Delivery / Dine-in)
- BorderBeam animation for 3 seconds on new card arrival (mirrors KdsOrderCard)
- Item list below header — one row per non-scratch item

**Item row (batch_prepared / ready_to_sell):**
- Item name 18px, quantity badge
- Preparation type badge: "Batch Prepared" (info color) or "Ready to Sell" (muted)
- Tap/click row to mark item picked → row gets strikethrough + success icon + opacity-50

**Assemble item row:**
- Shows component checklist (indented below item name)
- Each component line: Checkbox + component recipe name + quantity
- Checkbox checked → strike through component name
- All components checked → "Mark Complete" button becomes active (primary)
- "Mark Complete" marks the assembly item as ready

**Card completion:** When all items in an order card are picked/assembled, card shows green "Order Ready" banner at bottom + auto-fades after 30s (mirrors KdsOrderCard fade-out).

---

### 5. Supply Usage Page (`/operations/kitchen/supply-usage`)

**Layout:** Two-column layout — matches Waste Log exactly:
- Left column (60% width on lg+): Supply usage history table
- Right column (40% width on lg+): "Log Usage" form Card
- Mobile: Tabs pattern (History / Log Usage)

**History table columns:** Date, Supply Name, Quantity Used, Unit, Notes, Logged By

**Table rows:** Same pattern as WasteLogRow — `hover:bg-muted/30 transition-colors`, `text-sm`, monospace for quantities.

**Log Usage form (mirrors WasteLogForm exactly):**
- Supply selector (Select — shows only ingredients with usage_type = 'supply')
- Quantity (Input, numeric, type=number, font-mono)
- Unit (Input, pre-filled from supply base_unit, editable)
- Notes (Textarea, optional, rows=2)
- Zone selector (Select)
- Submit button: "Log Usage" — full width, disabled while pending
- Success feedback: "Supply usage logged." toast (sonner) — no cost impact card (supplies have no cost_impact field)

---

### 6. Ingredient Categories Management

**Location:** Not a standalone page. Placed as a collapsible section at the bottom of the existing Ingredients page (`/operations/ingredients`).

**Component:** A Card titled "Ingredient Categories" with:
- Table of existing categories (name, is_default badge, sort_order, delete action)
- is_default = true → no delete button, shows "Default" Badge (muted)
- is_default = false → delete icon button (Trash2, destructive variant)
- "+ Add Category" button at bottom of table → opens inline Input row (not a dialog) with name field and checkmark confirm button

**Delete confirmation:** No dialog — inline destructive icon button. On click, button shows spinner while DELETE request is in flight. No undo.
