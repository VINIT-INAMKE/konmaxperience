## Token World

This phase operates exclusively in the `--public-*` warm token system established in Phase 23. All new components MUST use these tokens — never raw hex or shadcn's neutral `--background`/`--foreground` tokens in public-facing UI.

```
--public-bg:           oklch(0.98 0.005 80)   warm off-white page background
--public-fg:           #1c1917                primary text
--public-fg-subtle:    #44403c                secondary/supporting text
--public-muted:        #78716c                de-emphasised text, icons
--public-muted-warm:   #a1977e                light supporting text
--public-surface:      #f0ebe3                card + sheet backgrounds
--public-surface-alt:  #f0ebe3                alternate surface (same value, kept distinct)
--public-border:       #e8e0d4                primary border
--public-border-warm:  #e0d8cc                inner/nested borders
--public-border-light: #d6cfc4                lightest borders, dividers
--public-terracotta:   #c2410c                primary CTA, + buttons, active states
--public-terracotta-hover: #b13a0a            hover/pressed state for terracotta
--public-olive:        #365314                secondary CTA (e.g. "Delivered" badge)
--public-olive-hover:  #2d4510                hover state for olive
--public-accent:       #a16207                amber accent (price highlight, quantity badge)
```

New token additions required for Phase 24:

```css
/* Add to globals.css :root { } block */
--public-cart-bar:     #1c1917                floating cart bar background (dark inverse)
--public-cart-bar-fg:  #fafaf9                floating cart bar text (warm white)
--public-tracking-active: #c2410c            active checkpoint color (terracotta)
--public-tracking-done:   #365314            completed checkpoint color (olive)
--public-tracking-pending: #d6cfc4           pending checkpoint color (light border)
```

Usage rule: `bg-[var(--public-terracotta)]` — always use the `var()` wrapper per project convention.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline quantity button padding |
| sm | 8px | Compact chip/badge internal padding, item card gap |
| md | 16px | Card internal padding, section gaps, form field spacing |
| lg | 24px | Section padding, sheet internal padding |
| xl | 32px | Page section breaks |
| 2xl | 48px | Major layout breaks |
| 3xl | 64px | Page-level bottom clearance (above floating cart bar) |

Exceptions:
- Floating cart bar: fixed height 64px, z-50, bottom-0, left-0, right-0. Page content gets `pb-16` (64px) to avoid overlap.
- Item quantity `+`/`-` touch targets: minimum 44px × 44px to meet mobile tap target guidelines (use `min-w-[44px] min-h-[44px]`).
- Category tab bar: 48px height, sticky below the public header at `top-14`.

## Typography

| Role | Size | Weight | Line Height | Token Usage |
|------|------|--------|-------------|-------------|
| Body | 14px | 400 (regular) | 1.5 | Default for descriptions, secondary text |
| Label | 16px | 500 (medium) | 1.4 | Item names, form labels, tab names |
| Heading | 20px | 600 (semibold) | 1.25 | Category section headers, sheet titles |
| Display | 28px | 600 (semibold) | 1.2 | Page-level "Our Menu" heading only |

Source: Observed in existing public pages — `text-base font-semibold` (16px/600), `text-sm text-[var(--public-muted)]` (14px/400), `text-xl font-semibold` (20px/600), `text-3xl font-semibold` (30px/600, which we normalise down to 28px for this phase).

Currency values (₹XX.XX) use the Label role (16px/500) with `text-[var(--public-fg)]`.

Total/subtotal amounts in cart use Heading role (20px/600).

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--public-bg` oklch(0.98 0.005 80) | Page background, scroll areas |
| Secondary (30%) | `--public-surface` #f0ebe3 | Item cards, cart bottom sheet, profile tabs, address cards |
| Accent (10%) | `--public-terracotta` #c2410c | See reserved-for list below |
| Destructive | `oklch(0.577 0.245 27.325)` via `--destructive` | Remove address (confirm dialog), remove cart item |

Accent (`--public-terracotta`) reserved for exactly these elements — nothing else:
1. The `+` add-to-cart button on item cards (initial add)
2. The quantity `+` and `-` stepper buttons
3. The [Pay ₹XXX] CTA button in the cart bottom sheet
4. The [Re-order] button on past order history cards
5. The active/selected state of channel toggle (Pickup / Delivery pill)
6. Active checkpoint dot on the order tracking timeline
7. Links and inline actions (resend OTP, "Change address")

Availability badge colors:
- Available: `bg-green-50 text-green-700 border-green-200` (consistent with existing AvailabilityBadge component)
- Unavailable: `bg-stone-100 text-stone-400 border-stone-200` + item card opacity reduced to `opacity-60`

Order status badge colors:
- Placed: `bg-blue-50 text-blue-700`
- Preparing: `bg-amber-50 text-amber-700`
- Ready / Out for Delivery: `bg-orange-50 text-orange-700`
- Delivered / Picked Up: `bg-green-50 text-green-700`
- Cancelled: `bg-stone-100 text-stone-500`

## Surfaces and Layout

### 1. /menu page — Enhanced with ordering

Layout: Single column, max-width `max-w-2xl mx-auto` (narrower than current `max-w-4xl` for mobile-first food app feel), `px-4`.

Structure (top to bottom):
```
[Public header — sticky, h-14, z-10]
[Category tab bar — sticky, top-14, h-12, z-9, bg-[var(--public-bg)] border-b border-[var(--public-border-light)]]
  horizontal scroll, no scrollbar visible (scrollbar-hide), gap-2, px-4
  each tab: px-4 py-2 rounded-full text-sm font-medium
  active tab: bg-[var(--public-terracotta)] text-white
  inactive tab: bg-[var(--public-surface)] text-[var(--public-fg-subtle)] border border-[var(--public-border)]
[Scrollable content — pt-4 pb-16]
  category sections anchor-scroll on tab click
  each section: space-y-3
    section heading: text-lg font-semibold text-[var(--public-fg)] sticky top-[6.5rem]
    item list: flex flex-col gap-2 (single column list, NOT grid — Swiggy/Zomato pattern)
[Floating cart bar — fixed, bottom-0, h-16, z-50]
```

Layout: Horizontal card (image left, info right), NOT the current square grid card.

```

  [Left: info flex-1]

  [Unavailable overlay: opacity-60, + button disabled bg-stone-300 cursor-not-allowed]
```

## Interaction States

### Add to cart button

| State | Visual |
|-------|--------|
| Default (qty=0) | Small `+` circle, 28px, terracotta |
| Adding (optimistic) | Immediate increment — no loading spinner (local state) |
| qty>0 | Inline stepper: `- {N} +` on terracotta pill |
| Unavailable | Grey `+` with cursor-not-allowed |

### Cart bottom sheet

| State | Visual |
|-------|--------|
| Opening | Sheet slides up from bottom (default shadcn Sheet animation) |
| Channel toggle | Smooth bg transition on pill selection |
| Address loading | Skeleton line (h-4 w-full) for address suggestion list |
| Pay button loading | Loader2 + "Processing..." text, button disabled |
| Razorpay open | Sheet stays visible behind Razorpay overlay |
| Payment success | Sheet closes, toast "Order placed!", redirect to /orders/[id]/track |
| Payment failed | Error banner inside sheet, button re-enabled |
| Cart empty (all qty 0) | Sheet auto-closes, floating bar disappears |

### Order tracking timeline

| State | Visual |
|-------|--------|
| New checkpoint arriving | BlurFade slide-up animation on new row |
| Active checkpoint dot | `animate-pulse` ring around terracotta dot |
| Pusher disconnected | Subtle amber "Reconnecting..." banner under header |

### Re-order flow

| State | Visual |
|-------|--------|
| Cart is empty | Adds items silently, floating cart bar appears |
| Cart has items | Dialog: "Replace your cart or add to it?" with [Replace] [Add to cart] [Cancel] |
| Some items unavailable | Toast: "Dosa was skipped — currently unavailable" after re-order completes |

## Accessibility Notes

- All `+`/`-` quantity buttons must have `aria-label="Increase quantity of {item}"` / `aria-label="Decrease quantity of {item}"`
- Cart bottom sheet must trap focus when open (shadcn Sheet does this by default)
- Order tracking timeline uses `role="list"` and `role="listitem"` on checkpoints
- Active tracking step has `aria-current="step"` attribute
- Address autocomplete dropdown uses `role="listbox"` + `role="option"` + keyboard navigation
- Floating cart bar has `aria-live="polite"` on item count to announce changes to screen readers
- Receipt page has no interactive elements — static HTML only
