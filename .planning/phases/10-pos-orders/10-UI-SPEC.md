## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, qty button inner spacing |
| sm | 8px | Card inner row gaps, inline element spacing |
| md | 16px | Card padding, section gaps, sidebar field spacing |
| lg | 24px | Panel padding, menu category header spacing |
| xl | 32px | Layout column gap between menu grid and cart sidebar |
| 2xl | 48px | Major section breaks on order history page |
| 3xl | 64px | Page-level top padding (non-POS pages only) |

Exceptions:
- Menu item tap targets: minimum 44px height (touch accessibility on tablet)
- Quantity +/- buttons: 32px x 32px minimum (comfortable tap target on terminal)
- Full-screen POS: 0px top padding (no page header, edge-to-edge layout)

|------|------|--------|-------------|-------|

| Label | 12px | 600 | 1.4 | Section headers, badge text, status pills, "X left" servings label, food cost % |

Source: Established in KdsOrderCard (28px/bold order #), MenuItemCard (16px/semibold name, 14px price) — applied consistently.

## Color

All values are CSS custom properties from `globals.css`. Reference by token, not hex.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` oklch(1 0 0) light / oklch(0.145 0 0) dark | Full POS page background, order history page, delivery queue page |
| Secondary (30%) | `--card` oklch(1 0 0) light / oklch(0.205 0 0) dark | Menu item cards, cart sidebar panel, order detail card, payment form card |
| Accent (10%) | `--primary` oklch(0.205 0 0) light / oklch(0.922 0 0) dark | Reserved — see list below |
| Destructive | `--destructive` oklch(0.577 0.245 27.325) light / oklch(0.704 0.191 22.216) dark | Cancel order button only |

Accent (`--primary`) reserved for:
1. "Place Order" CTA button (primary action in cart sidebar)
2. "Record Payment" CTA button (primary action on order detail)
3. Active/selected brand tab indicator
4. Quantity +/- button active state (filled background on tap)

Additional semantic colors (status badges — use background tints, not full saturation):
- `placed`: `bg-blue-500/15 text-blue-600` — order placed, awaiting kitchen
- `preparing`: `bg-amber-500/15 text-amber-600` — kitchen is working
- `ready`: `bg-emerald-500/15 text-emerald-700` — ready for service
- `served` / `dispatched`: `bg-muted text-muted-foreground` — completed
- `cancelled`: `bg-destructive/10 text-destructive` — cancelled
- `paid`: `bg-emerald-500/15 text-emerald-700`
- `pending` (payment): `bg-amber-500/15 text-amber-600`
- `refunded`: `bg-blue-500/15 text-blue-600`

Servings-remaining badge color logic:
- 6+ servings: `bg-emerald-500/15 text-emerald-700`
- 2–5 servings: `bg-amber-500/15 text-amber-700` (low stock warning)
- 1 serving: `bg-red-500/15 text-red-700` (urgent)
- 0 servings (sold out): item card `opacity-60`, overlay "Sold Out" label, card is non-interactive

MagicCard gradient: `#1a1a2e` (established project-wide in Phase 2 decision)

## Layout Contracts

### POS Page (`/pos`)

Split-screen layout — 2/3 + 1/3:

```
┌─────────────────────────────────────────┬───────────────┐
│  LEFT: Menu Grid (flex-1 or ~66%)       │  RIGHT: Cart  │
│  ┌─────────────────────────────────┐    │  Sidebar      │
│  │ Brand Tabs (sticky top)         │    │  (~33%)       │
│  ├─────────────────────────────────┤    │               │
│  │ Category Section Header         │    │  Channel      │
│  │ ┌──────┐ ┌──────┐ ┌──────┐     │    │  selector     │
│  │ │ Item │ │ Item │ │ Item │     │    │               │
│  │ │ Card │ │ Card │ │ Card │     │    │  Channel      │
│  │ └──────┘ └──────┘ └──────┘     │    │  fields       │
│  └─────────────────────────────────┘    │               │
│                                         │  Item rows    │
│                                         │               │
│                                         │  Subtotal     │
│                                         │  Channel mod  │
│                                         │  Total        │
│                                         │               │
│                                         │ [Place Order] │
└─────────────────────────────────────────┴───────────────┘
```

- Left panel: `flex-1 overflow-y-auto` with brand Tabs sticky at top (not a nav — use shadcn Tabs)
- Right panel: `w-80 min-w-[320px] border-l border-border flex flex-col` (fixed width, full height)
- Cart sidebar scrolls independently for long item lists
- Full-screen toggle: button in top-right of POS page header → sets `fixed inset-0 z-50 bg-background` class, hides sidebar nav entirely. Exit button (X) in top-right corner restores layout.
- Responsive: POS is desktop/tablet only. No mobile breakpoint required (staff terminal use).

### Menu Item Card (POS variant)

Different from the ops MenuItemCard — optimized for tap speed, NOT management actions.

```
┌────────────────────────────┐
│ Item Name          [X left]│  ← servings badge top-right
│ INR {price}                │
│ ─────────────────────────  │
│         [+ Add]            │  ← full-width tap target
└────────────────────────────┘
```

- Card size: minimum 140px wide, 120px tall (comfortable tap target)
- Grid: `grid-cols-3 gap-3` within each category section
- Sold out state: `opacity-60 pointer-events-none`, "Sold Out" label replaces servings badge, no Add button
- Tap "+ Add" adds 1 qty to cart and shows NumberTicker briefly on badge (if already in cart, increments)

### Cart Sidebar Item Row

```
Item Name (14px/400)          ─    {qty}    +
                          INR {line_total}
```

- Qty adjustment: two buttons (− and +) flanking a quantity display. No number input field — tapping is faster.
- Minimum qty is 1; pressing − at 1 removes the item from cart (no confirmation needed — fast workflow).
- Line total updates immediately (optimistic, no API call until Place Order).

### Cart Channel Section

Shown below item list, above total:

```
Channel: [Dine-in ▾] [Takeaway ▾] [Delivery ▾]  ← 3 segmented buttons
─────────────────────────────────
  [Dine-in selected]   Table #: [___]
  [Takeaway selected]  Customer phone: [___]
  [Delivery selected]  Phone: [___]
                       Address: [___________]
                       Assigned to: [___]
─────────────────────────────────
  Notes: [optional notes field]
```

- Channel selector: use shadcn Tabs (variant="outline") in the sidebar, compact `h-8` height
- Fields appear/disappear based on channel selection (conditional render, no animation)
- All channel-specific fields are shown inline — no modal, no drawer, consistent with D-05

### Order History Page (`/pos/orders`)

Standard full-page layout (sidebar visible):

- Top: Daily revenue summary strip — 3 stat cards (Total Orders, Total Revenue, Avg Order Value) using NumberTicker for animated values
- Below: Filter bar (date range picker, channel select, status select, payment method select) + search input
- Main: shadcn Table — columns: Order #, Time, Channel, Items, Total, Payment Status, Order Status, Actions
- Row click: opens order detail in a Sheet (right-side drawer, 520px width)

### Order Detail Sheet

Inside the Sheet:
- Header: Order # (Display typography), channel badge, status badge, timestamp
- Items table: item name, qty, unit price, line total
- Channel fields section: shows table number / phone / address depending on channel
- Order status progression: horizontal step indicator (placed > preparing > ready > served/dispatched)
- Payment section: if no payment recorded — "Record Payment" button; if recorded — payment details (method, amount, notes)
- Delivery section (delivery channel only): delivery_assigned_to text input + delivery_status step buttons (picked_up > in_transit > delivered)
- Cancel order button (destructive, at bottom, requires confirmation dialog)

### Delivery Queue Page (`/pos/delivery`)

- Full-page table of active delivery orders (status != delivered, != cancelled)
- Columns: Order #, Customer, Address, Assigned To, Delivery Status, Actions
- Inline "Assign" button opens a small Popover with a text input for delivery_assigned_to name
- Status advance buttons inline in the row (picked_up > in_transit > delivered)

## Interaction Contracts

### Tap-to-Add (POS primary flow)

Target: complete order in under 30 seconds (CONTEXT.md specifics D-01).

1. Staff taps menu item card → item added to cart (AnimatedList slide-in) → servings badge decrements immediately (optimistic)
2. Tap again on same item: quantity increments (no duplicate row — single row with updated qty)
3. Tap "−" at qty 1: item removed from cart (AnimatedList slide-out)
4. No loading state between tap and cart update — all local state until "Place Order"

### Place Order

1. Staff fills channel + channel-specific fields (all required for selected channel)
2. "Place Order" button active only when: cart has at least 1 item AND channel is selected AND required channel fields are filled
3. On click: POST /orders — optimistic disable of button + spinner inside PulsatingButton
4. On success: Sonner toast "Order #XXXX placed", cart resets to empty, BorderBeam flashes cart sidebar, servings counts refetch
5. On error: Sonner toast error message, cart preserved (staff can retry)

### Servings Remaining Polling

- Servings availability fetched from GET /menu/availability/:menuItemId (Phase 9 endpoint)
- Polled every 10 seconds on the POS page (matches KDS metrics bar pattern from Phase 9 decision)
- Sold-out state applied immediately after Place Order (optimistic update before refetch)

### Record Payment

1. Staff clicks "Record Payment" on order detail Sheet
2. Inline form appears within the Sheet (no separate page): method select, amount input, notes textarea
3. Submit: POST /orders/:id/payment — spinner on button
4. On success: Sheet re-renders with payment details, "Record Payment" button replaced with paid status
5. Notes field placeholder: "e.g. Split — cash ₹300 + UPI ₹200" (split description guidance)

### Cancel Order

1. Staff clicks "Cancel Order" (destructive) on order detail Sheet
2. Dialog: "Cancel Order #XXXX? This cannot be undone. Items on the KDS will be removed." + "Cancel Order" (destructive) + "Keep Order" (default)
3. On confirm: PATCH /orders/:id {status: "cancelled"} → Sheet closes, table row updates

### Full-Screen POS Mode

1. "Terminal Mode" button (ShimmerButton) in POS page header
2. On activate: page enters `fixed inset-0 z-50 bg-background overflow-hidden` — sidebar nav hidden, browser chrome not escaped (CSS only)
3. Exit button: `X` icon, `absolute top-4 right-4` position
4. State persisted in React state only (not URL, not localStorage) — refreshing exits terminal mode

### Delivery Status Advance

1. Inline buttons per row in delivery queue: "Mark Picked Up" → "Mark In Transit" → "Mark Delivered"
2. Only the NEXT status button shown (not all three) — reduces cognitive load
3. On click: PATCH /orders/:id {delivery_status: "..."} — row updates immediately (optimistic)
