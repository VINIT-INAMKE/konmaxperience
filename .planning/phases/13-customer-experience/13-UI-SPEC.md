# Phase 13 — UI Design Contract

> Visual and interaction contract for Phase 13: Customer Experience.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **DUAL CONTEXT:** This phase has two distinct layout surfaces.
> - **Public layout** — `(public)` route group. No sidebar, no auth. Routes: `/feedback/[orderId]`, `/events`, `/events/[id]`, `/menu`.
> - **Ops layout** — existing `(ops)` route group. Sidebar + auth. Routes: `/operations/feedback`, `/operations/events`.

## Layout Contexts

### Public Layout — `(public)` route group

```
┌───────────────────────────────────────────┐
│ Header: Konma logo · "Konma Xperience"    │  h-14 (56px), bg-background/95 backdrop-blur
│                                           │
│                [page content]             │  max-w-2xl mx-auto px-4 py-8 (mobile)
│                                           │  max-w-4xl on md+ (menu display / events grid)
│                                           │
│ Footer: "Powered by Konma Xperience"      │  h-10, text-xs text-muted-foreground, centered
└───────────────────────────────────────────┘
```

- **No sidebar.** No navigation links in header. Header is logo + name only.
- **Mobile-first.** Single-column on mobile, 2-column grid on md+ for events. Menu uses single-column with brand tabs.
- **Public layout is LIGHT theme.** Do not inherit dark class for public pages. The `(public)` layout must NOT apply the dark class — set `data-theme="light"` or wrap children in a light-themed container. Public pages are customer-facing: bright, warm, and inviting.
- **Ops pages inherit existing dark ops layout** — no changes to existing layout.

### Ops Layout — `(ops)` route group

Existing layout unchanged: sidebar + `main` with `p-6 max-w-[1200px] mx-auto`. New ops pages (`/operations/feedback`, `/operations/events`) follow the exact same page structure as existing ops pages.

## Spacing Scale

Declared values (multiples of 4, consistent with existing codebase):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, star rating gaps |
| sm | 8px | Between form label and input, badge padding |
| md | 16px | Card internal padding (mobile), form field gap |
| lg | 24px | Section spacing (`space-y-6`), page padding horizontal on sm+ |
| xl | 32px | Section breaks between major page sections |
| 2xl | 48px | Thank-you screen vertical centering pad |
| 3xl | 64px | Empty state vertical padding (`py-16`) |

Exceptions:
- **Touch targets on mobile**: star rating buttons minimum 44px touch area (`min-h-[44px] min-w-[44px]`), per mobile QR-scan use case
- **Public header**: fixed height 56px (`h-14`)
- **Public page max-width**: `max-w-2xl` (feedback, event detail) and `max-w-4xl` (events grid, menu) centered with `mx-auto`

## Typography

Two sub-contexts: public pages use slightly larger sizes for readability on phone screens.

### Public Pages (`/feedback`, `/events`, `/menu`)

Weights: **600 (semibold) + 400 (normal) only.**

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 28px (`text-3xl`) | 600 (`font-semibold`) | 1.2 | Page title ("Thank You!", event name on detail) |
| Heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.3 | Section headings, event card title |
| Body | 16px (`text-base`) | 400 (`font-normal`) | 1.6 | Form labels, event description, menu item name |
| Label/Small | 14px (`text-sm`) | 400 (`font-normal`) | 1.4 | Price, capacity status, badge text, helper text — use `uppercase tracking-wider` for visual distinction instead of heavier weight |

### Ops Pages (`/operations/feedback`, `/operations/events`)

Matches established ops typography pattern exactly.

Weights: **600 (semibold) + 400 (normal) only.**

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Page heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 | Page `<h1>` (source: inventory page pattern) |
| Body | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 | Table cells, descriptions, card body |
| Label | 14px (`text-sm`) | 600 (`font-semibold`) | 1.4 | Table headers — paired with `uppercase tracking-wider` for distinction |
| Micro | 12px (`text-xs`) | 600 (`font-semibold`) | 1.4 | Column headers, secondary metadata — paired with `uppercase tracking-wider` |

## Color

### Public Context (light theme)

Public pages render in light mode independent of the global dark default. The public layout sets a light background.

| Role | Tailwind token | Usage |
|------|----------------|-------|
| Dominant (60%) | `bg-white` / `bg-background` (light) | Page background, form surface |
| Secondary (30%) | `bg-muted` / `bg-card` | Event cards, section containers |
| Accent (10%) | `bg-primary` / `text-primary` | Submit button, star fill (active), "Book Event" CTA, availability badge (available state) |
| Destructive | `text-destructive` | Form validation errors only |
| Sold Out / warning | `text-muted-foreground` + `bg-muted` | "Sold Out" badge, disabled booking form state |
| Success / thank-you | `text-primary` + confetti burst | Thank-you screen only — post-submission state |

Accent reserved for: active star rating fill, primary submit/CTA buttons, "Available" badge background, booking confirmation inline message. Never on decorative elements or hover states alone.

### Ops Context (dark theme, inherited)

| Role | CSS token | Usage |
|------|-----------|-------|
| Dominant (60%) | `--background` (`oklch(0.145 0 0)`) | Page background |
| Secondary (30%) | `--card` (`oklch(0.205 0 0)`) | Cards, table background, filter bar |
| Accent (10%) | `--primary` (`oklch(0.922 0 0)`) | Action buttons, active filters |
| Destructive | `--destructive` (`oklch(0.704 0.191 22.216)`) | Delete actions only |
| Semantic amber | `text-amber-500` | Average rating highlight in stats card (consistent with low-stock alert pattern) |

## Interaction Contracts

### Feedback Form (`/feedback/[orderId]`)

1. **Load state**: Skeleton for order info area while fetching order. If order not found, show inline info message: "We couldn't find your order, but you can still leave feedback." Form renders regardless.
2. **Star rating**: 5 clickable stars. Hover previews fill up to hovered star. Selected rating fills stars permanently. Stars are required — submit button disabled until rating selected.
3. **Submission**: Button shows `Loader2` spinner during POST. On success, form fades out (200ms) and thank-you screen fades in with confetti burst. On error, inline error below button: "Couldn't submit your feedback — please check your connection and try again."
4. **Thank-you screen**: Static — no redirect, no auto-dismiss. Just the message + confetti. No back button.
5. **Validation**: Rating required (1-5). Comment optional. Name optional (max 100 chars). Phone optional (max 20 chars). Validate client-side before submission.

### Event Booking (`/events/[id]`)

1. **Capacity display**: "X spots left" updates to "Sold Out" when 0 remaining. When sold out, booking form fields are `disabled`, submit button replaced with "This event is full" text.
2. **Booking form**: Name (required), phone (required), number of guests (required, min 1, max = remaining spots). Guest count input is a number input with +/- stepper (not free text).
3. **Capacity check**: Client-side: disable submit if guests > remaining. Server-side: if race condition causes overbooking, show inline error: "Sorry, this event just filled up. No spots remain for [N] guests."
4. **Success**: Inline confirmation message below form replaces submit button area. No page reload. Message: "You're booked! We'll see you on [date]."
5. **Error**: Inline below submit button. Never toast on public pages — customer may not see toast on mobile.

### Digital Menu (`/menu`)

1. **Brand tabs**: One tab per active food brand. First brand selected by default.
2. **Availability**: Binary only — "Available" or "Sold Out". No servings count shown to customers (D-10).
3. **Image**: `next/image` with `object-cover` aspect-ratio-square (1:1) container. If `image_url` null, show placeholder with item initial letter (centered, muted background).
4. **No interactive elements**: Menu is display-only. No add-to-cart, no click actions on items. Cards are not clickable.
5. **Refresh**: Auto-refresh availability every 60 seconds via React Query `refetchInterval`. No manual refresh button shown.

### Ops Feedback Page (`/operations/feedback`)

1. **Stats card**: Always visible at top. Shows average rating (1 decimal) and total count. Skeleton while loading.
2. **Filter**: Tabs for All / 5★ / 4★ / 3★ / 2★ / 1★ + date range Select (Today / This Week / This Month / All Time). Filters combine.
3. **Table**: Columns: Rating (star icons, read-only), Comment (truncated at 80 chars with expand toggle), Customer, Order (link to order if order_id present), Date. No CRUD — feedback is read-only ops view.
4. **Order link**: Clicking order ID opens `/operations/orders/[id]` in new tab (or navigates — match existing pattern).

### Ops Events Page (`/operations/events`)

1. **Create/Edit**: Sheet slides in from right. All fields in Sheet. Same single-component create/edit pattern as ZoneForm/BrandForm (source: Phase 6 decision).
2. **Bookings**: "View Bookings" button on each event row opens BookingListSheet. Sheet shows name, phone, guests, booked-at for each booking. Read-only.
3. **Delete**: Requires confirmation Dialog. Dialog copy: "This will permanently remove the event and all its bookings." Two buttons: "Cancel" (secondary) + "Delete Event" (destructive variant).
4. **Capacity fill**: Progress indicator on event row showing `booked_guests / capacity` (e.g., "12 / 40"). Visual progress bar thin (4px height, `h-1`) below the numbers.

## Mobile Responsiveness Contracts (Public Pages)

Phase 13 is the first phase with genuine mobile-primary surfaces. All public pages must pass on 375px viewport width.

| Page | Mobile layout | Desktop layout |
|------|---------------|----------------|
| `/feedback/[orderId]` | Single column, full-width form, centered `max-w-sm` | Same — centered `max-w-md` |
| `/events` | Single-column card stack | 2-col grid (`md:grid-cols-2`) |
| `/events/[id]` | Single column, image above detail | 2-col: image left, detail+form right (`md:grid-cols-2`) |
| `/menu` | Single column, brand tabs scroll horizontally | Same — `max-w-4xl` centered |
| Menu item cards | Full-width item rows (name + price + badge) | Grid: `sm:grid-cols-2 lg:grid-cols-3` |

Touch targets: all interactive elements minimum 44×44px on public pages. This applies to star rating buttons, booking stepper, submit buttons.
