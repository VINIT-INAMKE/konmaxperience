## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, form helper text offset |
| sm | 8px | Button icon gap, compact list item padding, input prefix padding |
| md | 16px | Default form field spacing, card body padding, sidebar item padding |
| lg | 24px | Card padding, section headers, form group gap |
| xl | 32px | Page content top padding, between form and CTA |
| 2xl | 48px | Major section breaks, auth card vertical centering offset |
| 3xl | 64px | Page-level centering (auth layout max-width constraint) |

Exceptions:
- Touch targets for icon-only buttons: minimum 44px × 44px (accessibility requirement)
- Permission matrix toggle cells: 40px × 40px minimum (touch-friendly on tablet)
- Sidebar width: 240px (fixed, not from scale — standard sidebar proportion)

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (Regular) | 1.5 | Form labels, table cell text, sidebar nav items, helper text |
| Label | 13px | 500 (Medium) | 1.4 | Input labels, permission row labels, table column headers, badge text |
| Heading | 20px | 600 (Semibold) | 1.2 | Page titles, card headings, modal titles |
| Display | 28px | 700 (Bold) | 1.1 | Auth page headline ("Welcome back"), login page brand mark |

**Font family:** Geist Variable — `font-sans` for all text.
**Monospace exception:** User role codes (e.g. `FRONTEND_LEAD`) and token/ID display use `font-mono` (Geist Mono) at 12px, weight 400.
**Two weights for body text only:** Regular (400) and Medium (500). Semibold (600) and Bold (700) reserved for headings only.

## Color

| Role | Value (CSS Variable) | Light Mode | Dark Mode | Usage |
|------|---------------------|-----------|-----------|-------|
| Dominant (60%) | `--background` | `#FAFAFA` (neutral-50) | `#0A0A0A` (neutral-950) | All page backgrounds, auth page bg |
| Secondary (30%) | `--card` | `#FFFFFF` (white) | `#171717` (neutral-900) | Auth card, nav sidebar, user management table bg, settings panels |
| Accent (10%) | `--primary` | `#18181B` (neutral-900) | `#FAFAFA` (neutral-50) | Accent list below |
| Destructive | `--destructive` | `#DC2626` (red-600) | `#EF4444` (red-500) | Destructive actions only — see below |
| Muted | `--muted-foreground` | `#71717A` (neutral-500) | `#A1A1AA` (neutral-400) | Helper text, disabled states, secondary metadata |
| Border | `--border` | `#E4E4E7` (neutral-200) | `#27272A` (neutral-800) | All borders, dividers, table separators |

**Accent reserved for (explicit list):**
- Primary CTA buttons (Sign In, Save Changes, Create User)
- Active/selected sidebar nav item background
- Focus ring on form inputs
- Toggle switch thumb (active state)
- Loading spinner

**Accent NOT used for:**
- Informational text
- Secondary buttons (use border/ghost variant)
- Nav items that are not active
- Table rows or hover states

**Dark mode:** Default. The internal ops tool targets a focused work environment. Dark mode is the primary experience. Light mode must also be fully functional (some team members may prefer it; Tailwind `dark` class toggle).

**Semantic status colors** (used in Phase 1 for user status badges):
- Active: `#22C55E` (green-500 text on green-50 bg) / dark: green-400 on green-950
- Inactive: `--muted-foreground` text on `--muted` bg

## Layout Contracts

### Auth Layout (`(auth)/layout.tsx`)

- Full-viewport centered layout: `min-h-screen flex items-center justify-center`
- Background: `--background` with subtle noise texture or solid
- Card: centered, `max-w-[400px] w-full`, padding `lg` (24px), rounded-xl, border `--border`, shadow-sm
- Brand mark at top of card: "Konma Xperience" in Display typography + small role context subtitle
- No sidebar, no nav — auth pages are completely isolated

### Ops Layout (`(ops)/layout.tsx`)

- Two-column: fixed sidebar (240px) + flex main content area
- Sidebar bg: `--card` (slightly elevated from page bg)
- Sidebar sections: top = nav items, bottom = user avatar + name + role badge + dropdown
- Main content: padding `lg` (24px) all sides, `max-w-[1200px]` soft cap for very wide screens
- Page title sits at top of main content area at Heading size

### Admin Permission Settings Layout (`/admin/permissions`)

- Full-width table. Column 1 = Permission name (with tooltip on icon), Columns 2–8 = one column per role
- Each cell = centered Checkbox
- Role headers: Label typography, truncated if needed
- Sticky column 1 (permission name) on horizontal scroll
- Bulk "Save Changes" CTA at bottom-right, fixed to bottom of viewport on mobile

## Screen-Level Interaction Contracts

### Login Page (`/login`)

**Layout:** Auth card layout (see above)
**Elements:**
1. Brand headline: "Welcome back" (Display, centered)
2. Subtitle: "Sign in to Konma Xperience" (Body, muted, centered)
3. Email input — label "Email address", type="email", autocomplete="email"
4. Password input — label "Password", type="password", autocomplete="current-password", show/hide toggle (Eye icon, 44px touch target)
5. "Forgot password?" link — right-aligned below password field, Body size, accent underline on hover
6. Primary CTA button — full-width, "Sign in"
7. No "Remember me" checkbox — JWT 7-day expiry handles persistence (CONTEXT.md decision)

**States:**
- Default: fields empty, CTA enabled
- Loading: CTA shows spinner + "Signing in..." text, fields disabled
- Error: Alert component above form — "Incorrect email or password. Check your details and try again."
- Field validation: Inline below field — "Email is required" / "Password is required" (Label size, destructive color)
- Rate-limited: Alert — "Too many attempts. Try again in 5 minutes."

**Redirect behavior:** On success, redirect to `/(ops)/dashboard`. If `?redirect=` param present, redirect there instead.

### Forgot Password Page (`/forgot-password`)

**Layout:** Auth card layout
**Elements:**
1. Back arrow link to `/login` (top-left of card, sm icon + "Back to sign in")
2. Heading: "Reset your password" (Heading, centered)
3. Subtitle: "Enter your email and we'll send a reset link." (Body, muted, centered)
4. Email input — label "Email address"
5. Primary CTA — full-width, "Send reset link"

**States:**
- Default: field empty
- Loading: CTA shows spinner + "Sending..."
- Success state (replaces form): Icon (CheckCircle, accent) + "Check your email" heading + "We've sent a reset link to [email]. It expires in 15 minutes." body + "Resend email" ghost button (enabled after 60s countdown)
- Error: Alert — "No account found with that email address."

### Set Password Page (`/set-password?token=...`)

**Layout:** Auth card layout
**Elements:**
1. Heading: "Set your password" (Heading, centered)
2. Subtitle: "Create a password to access Konma Xperience." (Body, muted)
3. New Password input — label "Password", show/hide toggle
4. Confirm Password input — label "Confirm password", show/hide toggle
5. Password strength indicator — 3-segment bar below password field (weak/medium/strong — no text label, color only: destructive/amber-500/green-500)
6. Password requirements list (inline): "At least 8 characters", "At least one number" — check icon turns accent when met
7. Primary CTA — full-width, "Set password and sign in"

**States:**
- Passwords don't match: inline error below confirm field — "Passwords don't match"
- Expired token: full-card error — "This setup link has expired. Ask your admin to resend the invitation." with no form shown
- Used token: full-card error — "This link has already been used. Sign in or reset your password."
- Success: auto-redirect to `/login` with toast: "Password set. You can now sign in."

### Admin — Permission Settings (`/admin/permissions`)

**Layout:** Ops layout
**Page title:** "Permissions"
**Subtitle:** "Control what each role can view and do. Changes take effect within 60 seconds." (Body, muted)

**Permission matrix:**

- Columns: 7 non-admin roles (FOUNDER_ADMIN column is shown but all checkboxes are checked and disabled with a lock icon — admin permissions are not editable)

- Unsaved changes: a floating "Unsaved changes" banner appears at bottom of viewport with "Discard" ghost button and "Save changes" primary button

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Login CTA | "Sign in" | Verb only — no noun needed at this context |
| Forgot password CTA | "Send reset link" | Specific action |
| Set password CTA | "Set password and sign in" | Two outcomes, one action |
| Reset password CTA | "Reset password and sign in" | Parallel to set password |
| Create user CTA | "Add member" | Concise; "team member" in modal title provides context |
| Save permissions CTA | "Save changes" | Universal pattern; always paired with "Discard" |
| Empty state heading | "No team members yet" | Direct, no-filler |
| Empty state body | "Add your first team member to get started." | Tells the user the next step |
| Invalid credentials error | "Incorrect email or password. Check your details and try again." | Does not reveal which field is wrong (security) |
| Rate limit error | "Too many attempts. Try again in 5 minutes." | Exact time, no apology |
| Expired token error | "This link has expired. Ask your admin to send a new one." | Who to contact, what to do |
| Used token error | "This link has already been used. Sign in or reset your password." | Offers two paths |
| No email found (forgot pw) | "No account found with that email address." | Honest; this is an internal tool where user enumeration is not a concern |
| Deactivate user confirmation | "Deactivate [name]?" in dialog — body: "They will lose access immediately. You can reactivate them at any time." CTA: "Deactivate" (destructive) | Reversible, so no "permanent" language |
| Send reset email confirmation | No confirmation required — toast only: "Password reset email sent to [name]" | Low-stakes action |
| Invitation sent toast | "Invitation sent to [name]" | Personal, uses their name |
| Permissions saved toast | "Permissions updated" | Minimal confirmation |
| Password set success | "Password set. You can now sign in." | Redirects to login, toast persists |

## Destructive Actions

| Action | Trigger | Confirmation Pattern | Reversible |
|--------|---------|---------------------|------------|
| Deactivate user | Row action dropdown "Deactivate user" | Dialog modal — "Deactivate [name]?" + explanation + "Deactivate" (destructive) + "Cancel" buttons | Yes — admin can reactivate |

No hard-delete actions in Phase 1. User deactivation sets `status = inactive`, never deletes.

## Interaction States (Global)

All interactive elements must implement these states:

| State | Visual Treatment |
|-------|----------------|
| Default | As specified per component |
| Hover | 5-10% bg lightness shift; cursor: pointer |
| Focus | 2px solid accent ring, 2px offset — meets WCAG 2.1 AA |
| Active/Pressed | Slight scale: 0.98 or increased bg darkness |
| Disabled | 40% opacity, cursor: not-allowed, no hover effect |
| Loading | Spinner replaces or prefixes label; element disabled; width preserved (no layout shift) |
| Error | Destructive border on input + inline error text below |
| Success | Toast notification (top-right, 3-second auto-dismiss) |

## Motion Contract

Consistent with Notion/Linear aesthetic — motion is subtle and functional, not decorative:

| Interaction | Duration | Easing |
|-------------|----------|--------|
| Fade in (page/modal) | 150ms | ease-out |
| Slide in (sidebar, dropdown) | 150ms | ease-out |
| Toast entry | 200ms | ease-out (slide up + fade) |
| Toast exit | 150ms | ease-in (fade) |
| Button loading state | immediate (no animation) | — |
| Form error appearance | 100ms | ease-out |

Respect `prefers-reduced-motion`: all transitions reduce to instant (0ms) when OS setting is active.

## Accessibility Contract

- All form inputs have associated `<label>` elements (not aria-label only)
- Error messages are associated to inputs via `aria-describedby`
- Focus trap active within modals (Dialog component handles this via Radix)
- Color is never the only indicator of state (badges have text, error inputs have text message)
- Minimum contrast ratio: 4.5:1 for body text, 3:1 for large text (WCAG AA)
- Screen reader: all icons that carry meaning have `aria-label`; decorative icons have `aria-hidden="true"`
- Tab order follows visual reading order — no skip links needed (auth pages are single-focus flows)
