```prisma
model GuideSection {
  id           String      @id @default(uuid())
  title        String
  slug         String      @unique
  description  String?
  icon         String?
  accent_color String?
  sort_order   Int         @default(0)
  role_codes   String[]
  status       String      @default("draft")
  created_at   DateTime    @default(now())
  updated_at   DateTime    @updatedAt
  pages        GuidePage[]

  @@index([status])
  @@index([sort_order])
}

model GuidePage {
  id                  String       @id @default(uuid())
  section_id          String
  section             GuideSection @relation(fields: [section_id], references: [id], onDelete: Cascade)
  title               String
  slug                String
  sort_order          Int          @default(0)
  content             String       @db.Text
  summary             String?
  estimated_read_time Int?
  status              String       @default("draft")
  created_at          DateTime     @default(now())
  updated_at          DateTime     @updatedAt

  @@unique([section_id, slug])
  @@index([section_id, sort_order])
  @@index([status])
}
```

Key decisions enforced:
- `role_codes String[]` per D-01 (matches existing `Role.permissions String[]` pattern)
- `description String?` per D-03
- `icon String?` and `accent_color String?` per D-02
- `content String @db.Text` per D-04 (NOT Json type)
- `slug String` on GuidePage with `@@unique([section_id, slug])` per D-05/D-12
- `summary String?` and `estimated_read_time Int?` per D-05
- `status String @default("draft")` per D-07/D-09 (new sections start as draft)
- `onDelete: Cascade` on GuidePage.section_id — deleting a section deletes its pages (GUIDE-01/02)
- No outgoing FK references to any existing v1.0 model — migration must be additive-only

import { IsString, IsNotEmpty, IsNumber, IsIn, Min, Max } from 'class-validator';

export class PresignGuideDto {
