## Spacing Scale

Inherited from Phase 1 — no changes. All values confirmed in globals.css and Tailwind token usage.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline label offsets |
| sm | 8px | Button icon gap, compact list padding, kanban card inner padding (top/bottom) |
| md | 16px | Card body padding, form field spacing, kanban card horizontal padding |
| lg | 24px | Page section gaps, form group spacing, kanban column header padding |
| xl | 32px | Page content top padding, between progress section and task list |
| 2xl | 48px | Major section breaks (mission detail: between header and quest list) |
| 3xl | 64px | Page-level centering max-width constraint |

Exceptions (Phase 2 additions):
- Kanban column minimum height: 480px (ensures columns feel substantial even when empty)
- Kanban card: 12px vertical padding (between xs and sm — necessitated by card density; use `py-3` / 12px)
- Touch targets for drag handles, action icons, view toggle buttons: minimum 44px × 44px
- Progress bar height: 6px (core track) — uses `h-1.5` from shadcn Progress component
- Task type badge: 4px vertical / 8px horizontal padding — tight label at Label (13px) size

## Typography

Inherited from Phase 1. No new sizes or weights added.

| Role | Size | Weight | Line Height | Usage in Phase 2 |
|------|------|--------|-------------|-----------------|
| Body | 14px | 400 (Regular) | 1.5 | Task description, quest description, blocker reason text, dependency labels, table cell text, list view rows |
| Label | 13px | 400 (Regular) | 1.4 | Task type badge text, progress percentage annotations, column headers in list view, "Week 1" / "Week 2" week labels, metadata (due date, owner name) |
| Heading | 20px | 600 (Semibold) | 1.2 | Mission title (on detail page), Quest title (on detail page), Task title (on task detail), page-level titles ("Missions", "Blocked Tasks") |
| Display | 28px | 600 (Semibold) | 1.1 | Mission title on the Mission List page hero card (not used on all screens — reserved for primary mission name in list) |

**Two weights only:** Regular (400) and Semibold (600). No medium or bold.
**Monospace (inherited):** Mission/Quest/Task IDs, task type enum values — `font-mono` at Label size (13px), weight 400.

Phase 2 typography rules:
- Kanban card title: Body (14px) weight 600 — exception to the "two weights" rule for scannability in dense kanban. This is the only place weight 600 is used at Body size.
- Empty kanban column label: Label (13px) weight 400, muted color — "No tasks" text in empty columns
- Progress percentage: Label (13px) weight 600, displayed inline next to the progress bar label

## Color

Inherited from Phase 1. Phase 2 adds semantic status and task-type colors.

| Role | CSS Variable | Dark Mode Value | Usage |
|------|-------------|-----------------|-------|
| Dominant (60%) | `--background` | `oklch(0.145 0 0)` ≈ #0A0A0A | All page backgrounds, kanban board background |
| Secondary (30%) | `--card` | `oklch(0.205 0 0)` ≈ #171717 | Kanban cards, mission/quest cards, sidebar, form panels |
| Accent (10%) | `--primary` | `oklch(0.922 0 0)` ≈ #EBEBEB | Accent reserved-for list below |
| Destructive | `--destructive` | `oklch(0.704 0.191 22.216)` ≈ red-500 | Blocked badge, "Report blocker" button, blocker dialog CTA |
| Muted | `--muted-foreground` | `oklch(0.708 0 0)` ≈ #A1A1AA | Metadata text, week labels, empty state text, read-only task indicators |
| Border | `--border` | `oklch(1 0 0 / 10%)` | All card borders, kanban column borders, table dividers |

**Accent reserved for (explicit list — Phase 2):**
- "Create Mission" primary CTA button
- "Create Quest" primary CTA button
- "Create Task" primary CTA button
- "Save" / "Submit" buttons on all forms
- Active kanban column header underline (indicates current drag target)
- Focus ring on form inputs (inherited from Phase 1)
- View toggle button (active state: kanban selected)
- "Activate Quest" button (sets quest to active status, triggers baseline lock)

**Accent NOT used for:**
- Task type badges (use semantic colors below)
- Status badges (use semantic colors below)
- Progress bars (use semantic colors below)
- Ad-hoc task indicators (use amber — see below)
- Blocked badge (use destructive)

## Layout Contracts

### Inherited from Phase 1 (no changes)

- Auth layout: unchanged
- Ops layout: fixed 240px sidebar + flex main (padding `lg` / 24px, `max-w-[1200px]`)
- Sidebar: `--card` bg, role-scoped nav

### Mission List Page (`/(ops)/missions`)

- Ops layout wrapper
- Page header: "Missions" (Heading) left + "Create mission" primary button right (FOUNDER_ADMIN only — hidden for other roles)
- Mission cards: grid layout — `grid-cols-1 md:grid-cols-2 xl:grid-cols-3`, gap `lg` (24px)
- Each MissionCard: shadcn Card, padding `lg` (24px), shows: mission title (Heading), scope badge, phase badge, start→end dates (Label, muted), overall progress bar with percentage label, quest count (Label, muted)
- Sort order: active missions first (status=active), then planned, then completed — within each group sorted by start_date ascending
- Filter bar: below page header — Status filter (Select: All / Active / Planned / Completed), Scope filter (Select: All / Food / Art / Lifestyle / System / Mixed) — both inline, right-aligned

### Mission Create Form Page (`/(ops)/missions/new`)

- Ops layout wrapper
- Page header: back arrow ("← Missions") + "Create mission" (Heading)
- Full-page form: centered, `max-w-[680px]`, `mx-auto`
- Form sections with Separator between them:
  1. Basic info: Title (Input), Description (Textarea, 4 rows)
  2. Configuration: Phase (Select: Setup / Foundation / Activation / Scale), Scope (Select: Food / Art / Lifestyle / System / Mixed)
  3. Timeline: Start date (Input type="date"), End date (Input type="date", optional)
- Form footer: "Discard" ghost button (navigates back) + "Create mission" primary button — right-aligned
- Validation: all required fields marked, inline errors below each field

### Mission Detail Page (`/(ops)/missions/[id]`)

- Ops layout wrapper
- Page header: back arrow ("← Missions") + mission title (Heading) + phase badge + scope badge
- Mission meta row: start→end dates, status badge, overall progress bar full-width with percentage
- Section: "Quests" heading + "Add quest" button (FOUNDER_ADMIN only)
- Quest cards below: stacked list of QuestCards (not grid — quests are sequential weeks, vertical list reads better)
- Each QuestCard: Card component, shows quest title, "Week N" label (relative), role owner badge, dual-track progress (see progress contract below), task count, status badge
- Click QuestCard → navigate to `/quests/[id]`

### Quest Detail Page (`/(ops)/quests/[id]`)

- Ops layout wrapper
- Page header: breadcrumb "Missions / [Mission Title] / [Quest Title]" (Label, muted) above Heading title
- Quest meta row: "Week N", owner badge, status badge, start→end dates
- Dual-track progress section (below meta row)
- Task view toggle: kanban | list (toggle control, right side of tasks section header)
- Task section header: "Tasks" (Heading) + task count + "Add task" button (CREATE_TASK perm) + "Add ad-hoc task" button (CREATE_ADHOC_TASK perm, amber accent)
- Task view: kanban board (default) or list view depending on toggle
- "Add ad-hoc task" from quest page opens the same Sheet component used by sidebar shortcut, with quest pre-selected

### Quest Create Form Page (`/(ops)/missions/[id]/quests/new`)

- Ops layout wrapper
- Back arrow: "← [Mission Title]"
- Page title: "Add quest" (Heading)
- Form: centered, `max-w-[560px]`
- Fields: Title (Input), Description (Textarea, 3 rows), Week number (Input type="number", min=1, label="Week (relative to mission start)"), Role owner (Select — all 8 roles), Expected core task count (Input type="number", min=0, label="Expected core tasks", helper text: "This locks the baseline for core progress. Can set to 0 and activate later.")
- Form footer: "Discard" + "Add quest" primary button

### Kanban Board Layout (task view on Quest Detail)

- Four columns: "To Do" / "Doing" / "Done" / "Blocked"
- Column layout: `grid-cols-4 gap-4`, columns scroll independently via ScrollArea
- Column header: column label (Label, 13px, weight 600) + task count badge — color-coded per status (see color contract)
- Column min-height: 480px; each column has `overflow-y: auto` via ScrollArea
- Kanban card (TaskKanbanCard): Card component, left border 3px colored by status, padding `py-3 px-4` (12px/16px)
  - Card header: task title (Body 14px weight 600, truncated at 2 lines)
  - Card body: type badge + priority badge + owner avatar (16px) + owner name (Label, muted)
  - Card footer: due date (Label, muted) + dependency indicator (if has blocked dependency: red warning icon + "Blocked by: [task title]")
  - Ad-hoc tasks: amber left border (instead of status color) + amber "Ad-hoc" badge in top-right corner
  - Blocked tasks: red left border, "Blocked" badge (destructive), hover shows blocker reason in Tooltip
  - Drag handle: appears on hover — 6-dot grip icon (lucide GripVertical), 44px touch target
- Dropping a card into "Blocked" column: opens BlockerDialog (not automatic — requires reason)
- Empty column: centered Label text "No tasks" (muted)

### List View Layout (task view on Quest Detail)

- shadcn Table component
- Columns: Title | Type | Status | Priority | Owner | Due Date | Dependencies | Actions
- Title column: Body text, truncated at 1 line — click navigates to task detail
- Type column: colored badge (Core/Ad-hoc/Improvement per color contract)
- Status column: colored badge
- Priority column: colored badge (High: red, Medium: amber, Low: muted)
- Owner column: Avatar (20px) + name (Label)
- Due Date column: formatted "Mar 25" — overdue dates in destructive color
- Dependencies column: "None" or "Blocked by [title]" (truncated) with red warning icon if dependency incomplete
- Actions column: dropdown-menu — "View", "Edit", "Report blocker" (for own tasks), "Mark done" (for own tasks)
- Sortable columns: Title, Status, Due Date, Priority — click header to toggle asc/desc
- Table filter bar: Owner filter (Select — shows team members), Status filter (Select), Type filter (Select)

### Task Create/Edit Form (`/(ops)/quests/[id]/tasks/new`)

- Ops layout wrapper
- Back arrow: "← [Quest Title]"
- Page title: "Add task" or "Edit task" (Heading)
- Form: centered, `max-w-[680px]`
- Fields:
  1. Title (Input, required)
  2. Description (Textarea, 4 rows, optional)
  3. Task Type (Select: Core / Ad-hoc / Improvement — when opened from ad-hoc injection, pre-set to Ad-hoc and disabled)
  4. Priority (Select: High / Medium / Low)
  5. Assigned to (Select — team members list, required)
  6. Due date (Input type="date", optional)
  7. Depends on task (Combobox/Popover: search tasks by title within same mission — shows task title + current status + owner)
  8. XP value (Input type="number", read-only, auto-populated based on task type: Core=100, Ad-hoc=70, Improvement=80 — display only)
- Form footer: "Discard" + "Add task" / "Save changes" primary button

### Task Detail Page (`/(ops)/tasks/[id]`)

- Ops layout wrapper
- Breadcrumb: "Missions / [Mission] / [Quest] / [Task Title]" (Label, muted)
- Page header: task title (Heading) + status badge + type badge (colored) + priority badge
- Two-column layout (at md breakpoint): left column (2/3 width) = details, right column (1/3 width) = metadata sidebar
- Left column:
  - Description section (Body text, or muted "No description" if empty)
  - Dependencies section: "Depends on" card — task title + status badge + link to dependent task; or muted "No dependencies"
  - Blockers section (if blocked=true): red alert card — blocker reason text + "Unblock task" button (admin only)
  - Evidence section placeholder: muted card — "Evidence and approvals coming in Phase 3" — ensures the page has room for Phase 3 additions
- Right column (metadata):
  - Quest: linked (Label + link)
  - Mission: linked (Label + link)
  - Week: "Week N" (Label)
  - Assigned to: Avatar + name (Label)
  - Created by: Avatar + name (Label, muted)
  - Due date: date string (Label) — overdue in destructive color
  - XP value: "N XP" (Label)
  - Status: Badge with "Change status" inline dropdown (own tasks only)
  - Created: relative time (Label, muted)
- Footer action row: "Report blocker" ghost button (destructive variant, own task only) + "Mark as done" primary button (own task, status != done) OR "Reopen" ghost button (own task, status = done)
- Read-only view for tasks owned by others: all metadata visible, no edit controls, no action buttons, muted "Read-only — this task belongs to [Owner Name]" banner below header

### Blocker Dialog

- Triggered by: "Report blocker" action on task detail, or kanban card drop into Blocked column
- Pattern: Dialog (modal) — NOT Sheet
- Title: "Report a blocker" (Dialog title)
- Body: "What is blocking this task? Be specific so your admin can help resolve it."
- Field: Textarea (required), placeholder: "e.g. Waiting for supplier confirmation on ingredient list"
- Footer: "Cancel" ghost + "Report blocker" destructive button
- On submit: task status → blocked, blocked=true, blocked_reason set; toast: "Blocker reported. Admin has been notified."

### Ad-hoc Task Injection Sheet (Global Sidebar Shortcut)

- Triggered by: "+" button in sidebar (FOUNDER_ADMIN only, always visible) OR "Add ad-hoc task" button on quest page

- Step 2 (always shown, or step 1 if opened from quest page with quest pre-selected): Full task form (identical to Task Create form but task_type pre-set to Ad-hoc and disabled, quest pre-selected)
- Sheet footer: "Cancel" ghost + "Inject task" amber-accented primary button (not standard accent — amber signals ad-hoc)
- On submit: task created with task_type=adhoc; sheet closes; toast: "Ad-hoc task injected into [Quest Title]"

### Admin Blockers Overview (`/(ops)/admin/blockers`)

- Ops layout wrapper
- Page title: "Blocked Tasks" (Heading) + count badge (total blocked)
- Subtitle: "All currently blocked tasks across the system, oldest first." (Body, muted)

## Screen-Level Interaction Contracts

### Mission List Page

**States:**
- Loading: 3 skeleton MissionCards (Card with animated pulse bg)
- Empty (no missions): centered Rocket icon (lucide) + "No missions yet" heading + "Create your first mission to start building the roadmap." body + "Create mission" CTA (FOUNDER_ADMIN only)
- Error: Alert — "Could not load missions. Try refreshing the page."

### Mission Detail Page

**States:**
- Loading: skeleton for mission header + 2 skeleton QuestCards
- No quests yet: inline empty state within quests section — "No quests yet" (muted) + "Add the first quest" link (FOUNDER_ADMIN only)
- Progress states: progress bars animate from 0 to actual value on first mount (150ms ease-out)

### Quest Detail — Kanban Toggle

**Behavior:**
- Default view: kanban (persisted in Zustand client state per quest — survives page navigation within session)
- Toggle: click "List" → switches to list view; click "Kanban" → switches back
- Toggle control: two-segment button group — active segment has `--primary` bg, inactive has ghost style
- No animation between views — instant switch

### Drag-and-Drop (Kanban)

**Behavior:**
- Dragging: card lifts (shadow-lg, slight scale 1.02, 100ms ease-out)
- Valid drop target column: column background shifts to `--muted` (subtle highlight)
- Invalid drop (own-task check fails): card snaps back (200ms ease-in)
- Drop on "Blocked" column: triggers BlockerDialog before status change commits
- Drop on any other column: immediate optimistic update + PATCH /tasks/:id (status change)
- Non-own tasks: drag handle hidden, cards not draggable (`draggable={false}`)
- Keyboard drag: @dnd-kit keyboard sensor enabled — Tab to focus card, Space to pick up, Arrow keys to move, Space/Enter to drop

### Task Detail Page

**States:**
- Loading: skeleton layout (header + two-column content)
- Error 404: centered AlertCircle icon + "Task not found" heading + "Go back to quest" link
- Error 403: centered ShieldOff icon + "You don't have access to this task" + "Return to dashboard" link

### Blocker Dialog

**States:**
- Default: textarea empty, "Report blocker" button disabled
- Valid: textarea non-empty, "Report blocker" button enabled
- Submitting: button shows spinner + "Reporting..." text, textarea disabled
- Success: dialog closes, toast appears

### Ad-hoc Injection Sheet

**States:**
- Step 1 loading (missions list): Select shows "Loading missions..." disabled
- Step 2 enabled only when quest is selected
- Submit loading: "Inject task" → spinner + "Injecting..."
- Success: sheet closes, toast: "Ad-hoc task injected into [Quest Title]"

## Destructive Actions

| Action | Trigger | Confirmation Pattern | Reversible |
|--------|---------|---------------------|------------|
| Report blocker | "Report blocker" button on task card/detail | BlockerDialog — textarea for reason + "Report blocker" destructive CTA | Yes — admin can unblock |
| Drop task into Blocked column | Kanban drag-and-drop | BlockerDialog opens before status commits — must enter reason to confirm | Yes — admin can unblock |
| Unblock task | "Unblock" button on blockers overview / task detail | No confirmation dialog — single click action (reversible, low stakes) | Yes — can re-report blocker |
| Activate quest (baseline lock) | "Activate quest" button on quest detail | Confirmation Dialog — explains baseline_task_count will be locked; "Activate" + "Keep as planned" | NO — baseline_task_count is immutable after activation |

The quest activation dialog is the only irreversible action in Phase 2. It must clearly state the consequence before committing.

## Accessibility Contract (Inherited + Phase 2 Additions)

All Phase 1 accessibility rules apply. Phase 2 additions:

- Kanban drag-and-drop: @dnd-kit keyboard sensor enabled. Each draggable card has `aria-label="Drag to move [Task Title]"`. Columns have `role="region"` and `aria-label="[Column Name] column, [N] tasks"`.
- Progress bars: `aria-label="Core task progress: [N]%"` and `aria-label="Ad-hoc task progress: [N]%"` on each Progress component
- Status badges: text included (not color-only). "Blocked" badge has `role="status"`.
- Blocker reason: associated to blocked task via visible text on card — not tooltip-only for screen readers
- Task type badges: text label included ("Core", "Ad-hoc", "Improvement") — color is additive, not sole indicator
- View toggle (kanban/list): buttons have `aria-pressed="true/false"` and `aria-label="Kanban view"` / `aria-label="List view"`
- Breadcrumb navigation: `<nav aria-label="Breadcrumb">` with `<ol>` list structure
- Sheet: focus trapped within when open (Radix Sheet handles this); close button has `aria-label="Close panel"`
- Color is never the sole indicator: blocked tasks have text badge + border + tooltip; ad-hoc tasks have text badge + border; all status indicators have text
