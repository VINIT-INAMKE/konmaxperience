- Sheet component (same pattern as RecipeWizard from Phase 7-05)
- Props: `open: boolean`, `onOpenChange: (open: boolean) => void`, `onSuccess: () => void`
- State hoisted here: `step` (1|2|3), `recipeId`, `quantity`, `zoneId`, `previewLines: DeductionPreviewLine[]`
- Step indicator: 3 circles (32px x 32px per UI-SPEC spacing), active step gets `var(--primary)` accent color
- Headings per copywriting contract: Step 1 = "Create Prep Batch", Step 2 = "Review Deductions", Step 3 = "Confirm Batch"
- On step change, reset downstream state if going backwards (optional — simpler to keep state)
- "Next" button advances step: Step 1 -> Step 2 triggers POST /kitchen/prep-batches/preview, Step 2 -> Step 3 only if all lines sufficient

**2. Create PrepBatchWizardStep1** (`frontend/components/ops/kitchen/prep-batches/PrepBatchWizardStep1.tsx`):
- Props: `recipeId, setRecipeId, quantity, setQuantity, zoneId, setZoneId, onNext`
- Recipe select: fetch GET /recipes?status=approved, use Combobox (recipe list may be long per UI-SPEC component inventory) or Select if simpler. Display recipe name.
- Quantity input: number input, min 0.001
- Zone select: fetch GET /zones, Select component
- "Next" button enabled only when recipeId, quantity > 0, and zoneId are all set

**3. Create PrepBatchWizardStep2** (`frontend/components/ops/kitchen/prep-batches/PrepBatchWizardStep2.tsx`):
- Props: `previewLines: DeductionPreviewLine[]`, `isLoading: boolean`, `onNext, onBack`
- Table showing each BOM input: Input Name | Available Qty | Required Qty | Unit | Status
- Per D-01 / Interaction Contract:
  - When available < required: row background `destructive/10`, text `text-destructive`, show "Insufficient" Badge
  - When available >= required: normal styling, show "OK" or checkmark
- `allSufficient` = previewLines.every(l => l.sufficient)
- "Next" button disabled when ANY line is insufficient
- Disabled button tooltip per copywriting: "Insufficient stock for one or more inputs"
- Warning Alert (if any insufficient) per copywriting: "Insufficient stock — check inventory before starting this batch"
- "Back" button to return to Step 1

**4. Create PrepBatchWizardStep3** (`frontend/components/ops/kitchen/prep-batches/PrepBatchWizardStep3.tsx`):
- Props: `recipeId, quantity, zoneId, recipeName, zoneName, previewLines, onConfirm, onBack, isSubmitting`
- Summary display: Recipe name, Quantity, Zone name, deduction count
- "Start Batch" button (primary accent per UI-SPEC) — calls onConfirm
- "Back" button to return to Step 2
- While submitting: disable "Start Batch" button, show loading state

**5. Wire wizard in PrepBatchWizard:**
- Step 1 -> 2: POST /kitchen/prep-batches/preview with { recipe_id, zone_id, quantity_to_prep } using apiClient.post. Store result in previewLines state. Handle error with Sonner toast.
- Step 2 -> 3: Only proceed if allSufficient
- Step 3 confirm: POST /kitchen/prep-batches with { recipe_id, zone_id, quantity_to_prep } using apiClient.post. On success: Sonner toast success, call onSuccess (invalidates query), close Sheet, reset wizard state. On error: Sonner toast with error message per copywriting: "Failed to start batch. Check stock levels and try again."

**6. Update page.tsx:** Wire PrepBatchWizard Sheet with open state and onSuccess that invalidates 'prep-batches' query key via `queryClient.invalidateQueries`.
