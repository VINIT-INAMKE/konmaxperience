**2. `createPrepBatch(dto: CreatePrepBatchDto, userId: string)` — atomic deduction in $transaction:**

Implement inside `this.prisma.$transaction(async (tx) => { ... })`:

a) Fetch recipe with RecipeLines (include ingredient with base_unit, source_recipe with yield_unit)
b) Calculate multiplier = dto.quantity_to_prep / recipe.yield_qty

c) For each RecipeLine, calculate needed = line.quantity * multiplier:

If input_type === 'ingredient':
- Convert to base_unit: `const neededBase = await convertUnit(needed, line.unit, line.ingredient.base_unit, tx)` — MUST pass `tx` not `this.prisma` per Research Pitfall 2 / established Phase 8 pattern
- If neededBase is null, throw BadRequestException with conversion error message
- Fetch IngredientStock via `tx.ingredientStock.findUnique({ where: { ingredient_id_zone_id: { ingredient_id, zone_id } } })`
- If stock is null or Number(stock.current_quantity) < neededBase, throw BadRequestException('Insufficient stock for {ingredient.name}: need {neededBase} {base_unit}, have {available}')
- Decrement: `tx.ingredientStock.update({ where: ..., data: { current_quantity: { decrement: neededBase } } })`
- Create StockMovement: `tx.stockMovement.create({ data: { ingredient_id, zone_id: dto.zone_id, movement_type: 'prep_deducted', quantity: -neededBase, original_quantity: needed, unit: line.unit, reference_type: 'prep_batch', created_by: userId } })`

If input_type === 'recipe':
- Fetch active, non-expired PrepBatches: `tx.prepBatch.findMany({ where: { recipe_id: line.source_recipe_id, status: 'active', OR: [{ expires_at: null }, { expires_at: { gt: new Date() } }] }, orderBy: { created_at: 'asc' } })`
- Convert needed to batch unit if different: `convertUnit(needed, line.unit, batch.unit, tx)` (per Research Pitfall 2 — FIFO unit mismatch)
- Loop through batches FIFO: deduct = min(batch.quantity_remaining, remainingNeed), update batch (decrement quantity_remaining, set status='depleted' if quantity_remaining <= 0)
- If remainingNeed > 0 after all batches exhausted: throw BadRequestException('Insufficient prep batch stock for {source_recipe.name}')

d) Create the new PrepBatch:
```typescript
return tx.prepBatch.create({
  data: {
    recipe_id: dto.recipe_id,
    zone_id: dto.zone_id,
    quantity_produced: dto.quantity_to_prep,
    quantity_remaining: dto.quantity_to_prep,
    unit: recipe.yield_unit,
    prepared_by: userId,
    expires_at: recipe.shelf_life_hours
      ? new Date(Date.now() + recipe.shelf_life_hours * 3600000)
      : null,
    status: 'active',
  },
  include: { recipe: { select: { name: true } }, zone: { select: { name: true } } },
});
```

e) Set reference_id on StockMovements: after prepBatch is created, the StockMovements created above do NOT have reference_id set yet. There are two approaches: (1) create prepBatch first, then use its ID for StockMovements, or (2) create StockMovements without reference_id. Use approach (1) — create the PrepBatch record FIRST (before deductions), set reference_id on all StockMovements to the new prepBatch.id. Reorder: create PrepBatch -> deduct stocks (with reference_id) -> return. This is safe because the $transaction rolls back everything on error.

Actually, simpler: create the PrepBatch first without the deductions, get its ID, then do all deductions referencing that ID. If any deduction fails, the entire transaction rolls back including the PrepBatch creation.
