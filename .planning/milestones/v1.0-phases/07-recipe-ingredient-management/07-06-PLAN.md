**FoodCostBadge.tsx** (per D-07, UI-SPEC):
Props: percent (number | null).
- If null: `<span className="text-xs text-muted-foreground">Cost not available</span>`
- If < 30: `<span className="text-xs font-semibold text-green-500">{percent.toFixed(1)}%</span>`
- If 30-40: `<span className="text-xs font-semibold text-amber-500">{percent.toFixed(1)}%</span>`
- If > 40: `<span className="text-xs font-semibold text-red-500">{percent.toFixed(1)}%</span>`
Badge height 32px per UI-SPEC spacing exception.

**MenuItemCard.tsx** (per UI-SPEC):
Props: item (MenuItem), onEdit, onRemove, onToggleAvailability, isAdmin.
Layout per UI-SPEC:
- Row 1: item.name (heading 16px semibold)
- Row 2: Base price (`INR {base_price}` 14px) + FoodCostBadge (compute percent from recipe.computed_cost / base_price * 100 using calcFoodCostPercent)
- Row 3: Availability toggle (Switch component, inline label "Available"). On change: calls onToggleAvailability immediately. Show spinner icon for 500ms loading state.
- Row 4: "Edit" InteractiveHoverButton + "Remove" destructive icon (admin only)

**MenuItemForm.tsx** (per UI-SPEC):
Sheet form. Props: open, onOpenChange, categoryId (pre-selected), item (optional for edit), onSuccess.
Fields:
- Recipe (Combobox or Select — query GET /recipes?status=approved, only approved recipes per D-07 and Pitfall 5). Display recipe name.
- Category (Select — query GET /menu/categories, pre-select categoryId prop)
- Base Price (Input with INR prefix, number)
- Image URL (optional Input)
- Food cost % (read-only, auto-calculated): show `calcFoodCostPercent(selectedRecipe.computed_cost, basePrice)` live as user types price. Color updates live per UI-SPEC interaction pattern.
- Availability (Switch, default on)

On submit: POST /menu/items or PATCH /menu/items/:id. Toast "Menu item added" / "Menu item updated". Invalidate ['menu-items']. Call onSuccess.

Error handling: If recipe not approved, backend returns 400 — show toast with backend error message.

**Menu page** at `frontend/app/(ops)/operations/menu/page.tsx` (per D-06, D-08, D-09, UI-SPEC):

'use client' page.

Layout per UI-SPEC: Full-width. Header: "Menu" title (TextAnimate or display heading) + "Add Menu Item" button per brand tab.

**Brand tabs** at top — one tab per active food brand:
- Query: useQuery(['brands'], () => apiClient.get<Brand[]>('/brands'))
- Filter to food brands only: `brands.filter(b => b.brand_type === 'food' && b.status === 'active')`
- Use Tabs component (TabsList + TabsTrigger per brand)
- Active tab state: selectedBrandId (useState, default to first food brand)

**Data queries per brand tab:**
- Categories: useQuery(['menu-categories', selectedBrandId], () => apiClient.get<MenuCategory[]>(`/menu/categories?brand_id=${selectedBrandId}`))
- Items: useQuery(['menu-items', selectedBrandId], () => apiClient.get<MenuItem[]>(`/menu/items?brand_id=${selectedBrandId}`))
- Channel modifiers: useQuery(['channel-modifiers'], () => apiClient.get<ChannelModifier[]>('/menu/channel-modifiers'))

**Per-brand layout:**
Group items by category_id. For each category, render MenuCategorySection with its items.

**Category management:**
- "Add Category" button (when no categories exist or as action): opens a small Sheet/Dialog with fields: name (Input), sort_order (Input number, optional). POST /menu/categories with { name, brand_id: selectedBrandId, sort_order }.
- Edit category: inline edit or Sheet with name and sort_order.
- Delete category: Dialog confirmation per UI-SPEC — "Delete category [name]?" with warning about items being deleted.

**Menu item CRUD:**
- "Add Item" button on each MenuCategorySection opens MenuItemForm with pre-selected categoryId.
- Edit item: opens MenuItemForm in edit mode.
- Remove item: Dialog confirmation per UI-SPEC — "Remove [item name] from menu?"
- Availability toggle: PATCH /menu/items/:id with { available: true/false }. Toast per UI-SPEC: "Item marked as unavailable" / "Item marked as available". On error: revert toggle, toast "Failed to update availability. Try again."
