## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline chip padding |
| sm | 8px | Compact row spacing (`gap-2`), badge padding |
| md | 16px | Default element spacing (`gap-4`), card padding |
| lg | 24px | Section spacing (`space-y-6`), sheet padding |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Page-level top spacing |
| 3xl | 64px | Not used in this phase |

Exceptions: Touch targets on channel status toggle must be minimum 44px tall to prevent mis-tap on mobile. Use `h-11` on the Switch wrapper.

Source: Established in prior phases — `decisions/page.tsx` uses `space-y-6`, cards use `p-4`, header uses `gap-4`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.145 0 0)` dark / `oklch(1 0 0)` light | Page background (`bg-background`) |
| Secondary (30%) | `oklch(0.205 0 0)` dark / `oklch(0.985 0 0)` light | Cards (`bg-card`), sidebar (`var(--sidebar)`), Sheet panels |
| Accent (10%) | `oklch(0.97 0 0)` light-mode / `oklch(0.269 0 0)` dark-mode | Reserved list below |
| Destructive | `oklch(0.704 0.191 22.216)` dark / `oklch(0.577 0.245 27.325)` light | Delete zone, delete brand, delete asset — destructive actions only |

**Accent reserved for:**
- ShimmerButton shimmerColor `#4ade80` (green) — primary CTA on all four pages
- Active sidebar nav item highlight (`sidebar-accent`)
- Focused/hover state on interactive cards (`hover:bg-muted/20`)
- Tabs active trigger underline
- MagicCard `gradientColor="#1a1a2e"` spotlight effect on entity cards

**Status badge color mapping (semantic, not accent):**
- Zone: `planned` → amber-400, `setup` → blue-400, `active` → green-400, `inactive` → zinc-400
- Brand: `idea` → purple-400, `planning` → blue-400, `development` → cyan-400, `active` → green-400, `paused` → amber-400
- Channel: `planned` → amber-400, `active` → green-400, `inactive` → zinc-400
- Asset: `draft` → zinc-400, `in_review` → blue-400, `approved` → green-400, `rejected` → red-400

Source: `KpiStatusBadge.tsx` and `DecisionStatusBadge.tsx` establish the `text-{color}-400 border-{color}-500/30` pattern on `Badge variant="outline"`. All status badge colors follow this pattern.

## Page Layouts

### Zones Page (`/operations/zones`)

Layout: Card grid — functional admin panel, not flashy (CONTEXT.md specifics).

```
[BlurFade]
  [header row: "Zones" h1 | "Add Zone" ShimmerButton (admin only)]
  [filter bar: Tabs (All / Planned / Setup / Active / Inactive) | Search input]
  [grid: 3-col desktop, 2-col tablet, 1-col mobile]
    [ZoneCard × N] — MagicCard with zone type icon, name, status badge, owner avatar+name
  [ZoneForm Sheet]
```

**ZoneCard anatomy:**
- Row 1: Zone type icon (lucide, 16px) + zone name (`text-base font-semibold`) + ZoneStatusBadge
- Row 2: Owner avatar (size-5) + owner name (`text-sm text-muted-foreground`) + zone type label (`text-xs text-muted-foreground`)
- Row 3: InteractiveHoverButton "Edit" (admin or owner only) + notes preview if notes present

**Zone type icon mapping** (Claude's Discretion — resolved):
- `kitchen` → `ChefHat`
- `dining` → `UtensilsCrossed`
- `outdoor` → `Leaf`
- `workspace` → `Monitor`
- `storage` → `Archive`
- `leisure` → `Coffee`

### Brands Page (`/operations/brands`)

Layout: Card grid — identical structure to Zones page.

```
[BlurFade]
  [header row: "Brands" h1 | "Add Brand" ShimmerButton (admin only)]
  [filter bar: Tabs (All / Idea / Planning / Development / Active / Paused) | Search input]
  [grid: 3-col desktop, 2-col tablet, 1-col mobile]
    [BrandCard × N] — MagicCard with brand type badge, name, status badge, owner
  [BrandForm Sheet]
```

**BrandCard anatomy:**
- Row 1: Brand name (`text-base font-semibold`) + BrandTypeBadge (`food` / `art` / `lifestyle`) + BrandStatusBadge
- Row 2: Owner avatar (size-5) + owner name (`text-sm text-muted-foreground`)
- Row 3: InteractiveHoverButton "Edit" (admin or owner only) + created date (`text-xs text-muted-foreground ml-auto`)

**Brand status transition UI** (Claude's Discretion — resolved): Status dropdown inside the edit Sheet — not a separate button flow. Matches the evidence upload "submit then status changes" mental model. The Sheet contains: Name field, Type Select, Status Select (all valid status values), Owner Combobox (admin only).

### Channels Page (`/operations/channels`)

Layout: Table — channels are simple reference entities with a single toggle (CONTEXT.md D-11: "no complex configuration in v1").

```
[BlurFade]
  [header row: "Channels" h1 | "Add Channel" ShimmerButton (admin only)]
  [Table]
    [thead: Channel | Type | Status | Action]
    [tbody rows: ChannelRow × 7]
      [channel name | type badge | ChannelStatusToggle Switch | Edit button (admin only)]
  [ChannelForm Sheet]
```

**ChannelStatusToggle** (Claude's Discretion — resolved): Single `Switch` component — checked = active, unchecked = inactive/planned. Switch is disabled for non-admin users. Tooltip on Switch shows current status label. Wrapper `div` is `h-11` to meet 44px touch target.

**No search or filter tabs** on Channels page — 7 rows maximum, filtering is unnecessary.

### Assets Page (`/operations/assets`)

Layout: Table with filter tabs and upload action.

```
[BlurFade]
  [header row: "Assets" h1 | "Upload Asset" ShimmerButton]
  [filter bar: Tabs (All / Draft / In Review / Approved / Rejected) | Type filter Select | Search input]
  [Table]
    [thead: Name | Type | Brand | Status | Uploaded by | Date | Actions]
    [tbody rows: AssetRow × N]
  [AssetForm Sheet — contains AssetUploadZone]
```

**AssetRow anatomy:**
- Name: file icon (by asset type) + name (`text-sm font-medium`)
- Type: AssetTypeBadge (`text-xs`)
- Brand: linked brand name or `—` if not linked
- Status: AssetStatusBadge + status change dropdown (creator or admin only)
- Uploaded by: creator name (`text-sm text-muted-foreground`)
- Date: relative time (`text-xs text-muted-foreground`)
- Actions: "View" link (opens `url` in new tab) + "Delete" (creator or admin only)

**Asset type icon mapping:**
- `recipe` → `BookOpen`
- `sop` → `ClipboardList`
- `menu` → `List`
- `cost_sheet` → `DollarSign`
- `training_doc` → `GraduationCap`

**AssetUploadZone** — reuses EvidenceUploadZone pattern:
- Dashed border drop zone, `UploadCloud` icon centered
- `isDragging` state activates `BorderBeam` component
- XHR upload progress bar below zone
- Two-step: presign → PUT → create record (only on XHR success)

## Interaction Contracts

### Status Lifecycle Transitions

**Zones** (D-02: `planned → setup → active → inactive`):
- All 4 statuses selectable in edit Sheet — no linear enforcement. Admin and owner can set any status.
- No confirmation required for status changes.

**Brands** (D-06: `idea → planning → development → active → paused`):
- All 5 statuses selectable in edit Sheet. Admin and owner can set any status.
- No confirmation required for status changes.

**Channels** (D-10: `planned → active → inactive`):
- Switch toggle in table row — admin only. Toggling Switch cycles: planned → active → inactive → active (planned only visible at initial state; once activated, toggle is active ↔ inactive).
- No confirmation required for status toggle.

**Assets** (D-13: `draft → in_review → approved / rejected`):
- Creator can set `draft → in_review` via status select in edit form.
- Admin can set any status including `approved` and `rejected`.
- Status change triggers Sonner toast (see Copywriting Contract above).
- Assets with `approved` status: show green `ApprovedForDisplay` indicator label ("Ready for display").

### Delete Actions

All delete actions follow Dialog confirmation pattern:
- Trigger: "Delete" action in row/card
- Dialog opens with entity name and irreversibility warning
- Primary destructive button uses `variant="destructive"` (red)
- On confirm: DELETE request, query invalidation, Sonner toast "Zone deleted." / "Brand deleted." / "Asset deleted."
- No delete for channels (reference data).

### Asset Upload Flow (two-step)

1. User opens Sheet, fills name/type/brand fields, then drops or selects file in AssetUploadZone
2. ShimmerButton in Sheet footer is disabled until file selected
3. On submit: `POST /storage/presign-asset` → receive `presignedUrl` + `publicUrl`
4. XHR PUT to `presignedUrl` — progress bar shows during upload
5. On XHR success only: `POST /assets` with `{ name, asset_type, url: publicUrl, linked_brand_id?, status: 'draft' }`
6. Sheet closes, query invalidated, Sonner toast "Asset uploaded." + ShineBorder on new row for 3 seconds

### New Entity Highlight

ShineBorder applied to newly created Zone cards, Brand cards, and Asset rows for 3 seconds post-creation, then removed. Same pattern as `DecisionCard.tsx` (Phase 5).

### Form Behavior

All create/edit forms follow Sheet pattern:
- Sheet opens from right, `sm:max-w-md`
- Unsaved changes: no confirmation on close (acceptable for admin ops panel — form is short)
- Submit button: `ShimmerButton` with loading state during mutation
- Required fields: Name (all entities), Type (all entities), Brand (assets — required)
- Optional fields: Notes (zones), Owner (zones/brands — admin only), Brand link (assets), Task link (assets)
- Combobox for owner/brand selection (fetches live data)
