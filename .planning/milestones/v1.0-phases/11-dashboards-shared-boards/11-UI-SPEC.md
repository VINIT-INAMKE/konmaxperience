## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, stat card label gap |
| sm | 8px | Card inner row gaps, chart legend item spacing, kanban card content gaps |
| md | 16px | Card padding, dashboard widget internal padding, filter bar spacing |
| lg | 24px | Widget-to-widget gap in dashboard grid, section heading margin |
| xl | 32px | Column gap in multi-column dashboard grid, major section break on BI page |
| 2xl | 48px | Page section breaks (e.g. summary cards to charts to table) |
| 3xl | 64px | Page-level top padding where no page header exists |

Exceptions:
- Kanban column min-width: 240px (usability minimum for card content)
- Timeline feed item left indent: 24px (aligns with connector line visual)
- Chart container min-height: 200px (Recharts render requirement)
- Evidence feed thumbnail: 64px x 64px square (consistent aspect ratio)

Source: Spacing scale established Phase 1 and confirmed Phase 10 UI-SPEC. All exception values are multiples of 4.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 | 1.5 | Widget descriptions, table rows, timeline feed entries, evidence card meta, filter labels |
| Label | 12px | 700 | 1.4 | Section headers, badge text, status pills, chart axis labels, stat card sub-labels |
| Heading | 20px | 700 | 1.2 | Page section headings (e.g. "Revenue Trend", "Quest Board"), widget card titles |
| Display | 28px | 700 | 1.1 | Stat card primary values (revenue total, order count, food cost %) — use Geist Mono |

2 weights only: 400 (regular) for body and descriptive text; 700 (bold) for all headings, labels, stat values, and badge text. Dashboard surfaces are data-dense — high-contrast typography aids scan speed.

Notes:
- All monetary values (revenue, average order value, vendor spend): Geist Mono at 28px weight 700 in stat cards; Geist Mono at 14px weight 700 in table cells
- Food cost % values in recipe cost table: Geist Mono at 14px weight 700; highlighted rows (>40%) use `text-destructive` color
- Mission/quest progress percentages: 14px weight 700 (shown inside or beside progress bar)
- Kanban column count badge (e.g. "3 quests"): 12px weight 700 in `bg-muted` badge

Source: Typography contract established Phase 10 UI-SPEC. Carried forward unchanged.

## Color

All values are CSS custom properties from `frontend/app/globals.css`. Reference by token, not hex.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` oklch(1 0 0) light / oklch(0.145 0 0) dark | All dashboard page backgrounds, BI analytics page, boards pages |
| Secondary (30%) | `--card` oklch(1 0 0) light / oklch(0.205 0 0) dark | Stat cards, widget containers, kanban cards, evidence feed cards, timeline entries |
| Accent (10%) | `--primary` oklch(0.205 0 0) light / oklch(0.922 0 0) dark | Reserved — see list below |

1. Active time-range toggle button (Today / 7d / 30d active state on BI dashboard)
2. Primary CTA buttons ("Add Task" in ad-hoc injector, "Apply Range" in date range picker)
3. Mission card progress bar fill
4. Quest board kanban "In Progress" column header accent marker (left border, 3px)

Source: Color contract established Phase 1 and confirmed Phase 10 UI-SPEC. Identical token usage.

## Interaction Contracts

### Admin Dashboard: Pending Approvals Widget

1. Widget shows count badge + list of up to 5 most recent pending approvals (oldest first — longest waiting)
2. Each row: approval type, entity name, waiting duration (e.g. "2h 15m"), link to relevant page
3. "View all" link navigates to existing `/approval-queue` page
4. Widget refreshes on 60-second polling interval (low-urgency admin view, not real-time)
5. Empty state: "No pending approvals" with checkmark icon (positive signal)

### Admin Dashboard: Active Blockers Widget

1. Widget shows count badge + list of up to 5 blocked tasks
2. Each row: task name, quest name, blocked reason (truncated to 60 chars), link to task detail
3. "View all" link navigates to existing `/blockers` page (already built in Phase 2)
4. No polling — fetched once on page load (blockers are low-frequency events)
5. Empty state: "No active blockers" (positive signal)

### Admin Dashboard: Ad-hoc Task Injector Widget

1. Widget is a compact inline form Card — NOT a Sheet or Dialog (per CONTEXT.md "admin mission control feels actionable")
2. Fields: Title (required), Assign to (user Select), Quest (Select), Description (Textarea, optional)
3. "Add Task" button (primary, disabled until Title is filled)
4. On success: Sonner toast "Task added", form resets, related quest progress refetches
5. On error: Sonner toast error "Could not add task. Try again."
6. The widget is always expanded (no show/hide toggle) — it's the admin's fastest path to inject work

### Admin Dashboard: Recent Decisions Widget

1. Shows last 5 decisions (most recent first) in a compact list
2. Each row: decision title (truncated), type badge, status badge, timestamp
3. Click navigates to `/decisions` page (already built in Phase 5)
4. No "View all" needed — link to Decisions in sidebar is sufficient

### BI Dashboard: Time Range Toggle

1. Default on page load: 7d
2. Toggle tabs: Today | 7d | 30d | Custom
3. Switching tab immediately refetches all 4 queries (summary cards + revenue trend + top items + channel breakdown + recipe table) — all invalidate on `timeRange` state change
4. Custom: opens a Popover with a date range calendar. "Apply Range" button closes Popover and triggers refetch with `from` and `to` params.
5. Active tab: `--primary` background (per accent contract)

### BI Dashboard: Revenue Trend Chart

1. LineChart — `stroke="hsl(var(--chart-1))"`, `strokeWidth={2}`, dot shown on hover only (`activeDot`)
2. X-axis: date labels formatted as "Mar 15" (short format)
3. Y-axis: INR values formatted as "₹1.2k" for thousands (custom formatter)
4. Tooltip: shows exact date + exact revenue (e.g. "Mar 15 — ₹12,450")
5. No animation on data load (disable Recharts default animation for dashboard stability)
6. Empty state (no orders in period): chart area replaced with "No revenue data for this period" centered text at 14px muted-foreground

### BI Dashboard: Recipe Cost Analysis Table

1. Default sort: food cost % descending
2. Columns: Recipe Name | Computed Cost (₹) | Base Price (₹) | Food Cost % | Units Sold
3. Rows with food cost % > 40%: `bg-destructive/5` row background, food cost % cell `text-destructive font-bold`
4. "Units Sold" pulled from order history aggregation (new backend query needed)
5. Click on recipe row: navigates to `/operations/recipes/[id]` (existing detail page)
6. No inline editing in this table — read-only analysis view

### Quest Board: Kanban

1. Three static columns — no drag-and-drop in v1 (CONTEXT.md deferred ideas: "Custom dashboard widget arrangement — v2")
2. Each quest card: click navigates to the relevant mission/quest detail page
3. Filter by Mission or Assignee: React Query refilter (client-side if data volume is small; backend query if result set is large — planner decides)
4. "In Progress" column: sorted by progress % descending (most complete quests at top)
5. Column headers show count: "IN PROGRESS (4)" — count updates with filter

### Shared Boards: Evidence Feed

1. Default: all statuses, most recent first
2. Status filter: All | Pending | Approved | Rejected — client-side filter (evidence set is bounded)
3. Thumbnail: if evidence type is `photo`, shows `<img>` from evidence URL with `loading="lazy"` (no presigned URL needed — thumbnail-only, public CDN assumed)
4. "Load more evidence" loads next 20 records (cursor-based or offset pagination — planner decides)

### Wins/Milestones Timeline

1. Events sources: completed quests + validated tasks + level-ups (three separate query endpoints)
2. Merged and sorted by timestamp client-side before rendering
3. "Load more entries" adds 20 more entries
4. No filters in v1 — show all team members
