## Screen-Level Interaction Contracts

### Task Detail — Evidence Section

**Upload flow (file type):**
1. User drops file onto zone OR clicks "Upload evidence" ShimmerButton → file picker opens
2. Immediate client-side validation: size > 10 MB → Sonner error toast, no upload starts; MIME type not in allowlist → Sonner error toast
3. If valid: evidence item appears in list immediately with upload progress bar (optimistic — pending state)
4. `border-beam` activates on upload zone border during upload
5. XHR `upload.progress` events drive the blue progress bar fill
6. On XHR complete: call backend `POST /tasks/:id/evidence` to confirm → item status updates from "uploading" to "pending"
7. On XHR error: item shows error state with retry option — "Upload failed. Try again." (Label, destructive) + "Retry" ghost button inline

**Link submission flow:**
1. User clicks "Add a link" → `LinkEvidenceForm` slides down
2. User pastes URL + optional notes → "Save link" → `POST /tasks/:id/evidence` (type: link, no file upload)
3. Evidence item appears in list as `pending`
4. Sonner toast: "Link evidence submitted."

**Note submission flow:**
1. User clicks "Add a note" → `NoteEvidenceForm` slides down
2. User types note → "Save note" → `POST /tasks/:id/evidence` (type: note, no file upload)
3. Evidence item appears in list as `pending`
4. Sonner toast: "Note submitted."

**Approval flow (inline on task detail):**
1. Reviewer sees "Approve" and "Reject" `interactive-hover-button` actions on pending evidence
2. Click "Approve": `cool-mode` particle burst → `POST /evidence/:id/approve` → optimistic update to "approved" → `shine-border` on evidence card for 3 seconds → Sonner toast: "Evidence approved."
3. If this approval caused task to become valid: validation cascade fires → Sonner toast replaces previous: "Task validated! +{N} XP" with `text-animate` on "Task validated!" and `number-ticker` + `hyper-text` on the XP number → confetti burst (`confetti()` from canvas-confetti)
4. Click "Reject": opens Rejection Dialog → on submit: evidence status → rejected, rejection reason shown inline, Sonner toast: "Evidence rejected."

**Validation state change:**
- When task transitions from invalid → valid: `animated-circular-progress-bar` fills to 100%, checklist all items turn green simultaneously, confetti fires, Sonner success toast

**States:**
- Loading (evidence section): 3 skeleton evidence rows (animated pulse bg, same min-height 48px as real rows)
- Error loading evidence: Alert — "Could not load evidence. Try refreshing."
- Upload zone drag-over: dashed border → solid `--primary`, bg → `--muted` 50% opacity, upload icon color → `--primary`
- Upload zone drag-leave: reverts to default state, 100ms transition

### Approval Queue Page

**States:**
- Loading: 3 skeleton ApprovalItem cards (animated pulse)
- Empty: centered CheckCircle + "No pending approvals" + "You're all caught up."
- Error: Alert — "Could not load approvals. Try refreshing."
- Filter active (no results): "No approvals match your filter." (Body, muted, centered) — not same as empty state
- Submit loading: "Approve" → spinner replaces shimmer + "Approving..." text, button disabled
- Reject dialog submitting: "Reject evidence" → spinner + "Rejecting...", textarea disabled

3. `queryClient.invalidateQueries(['tasks', id])` and `queryClient.invalidateQueries(['quests', task.quest_id])` — after toast

| Interaction | Duration | Easing | Implementation |

## Accessibility Contract

All Phase 1 + Phase 2 accessibility rules apply. Phase 3 additions:

- Upload zone: `role="button"` on the drop zone div, `aria-label="Evidence upload zone — drop files here or click to browse"`, `tabIndex={0}`, keyboard: `Enter` / `Space` triggers file picker
- Upload zone drag state: `aria-describedby` pointing to helper text element with instructions
- Evidence status badges: text label included — never color-only. "Pending", "Approved", "Rejected" as text content
- Approval action buttons: `aria-label="Approve evidence from [Uploader Name]"` and `aria-label="Reject evidence from [Uploader Name]"` — identifies which evidence item is being acted on
- Rejection dialog: focus trapped within (Radix Dialog handles); textarea has associated label via `<Label>`
- Confetti: purely decorative — no ARIA announcements needed. Screen reader announcement of validation is via the Sonner toast (`toast.success()` which has `role="status"`)
- Validation checklist: `role="list"` on the checklist container, `role="listitem"` on each condition — enables screen reader navigation
- Validation checklist icons: CheckCircle and Circle icons have `aria-hidden="true"` — the text content carries the meaning
- Progress bar (upload): `aria-valuenow={progress}` `aria-valuemin={0}` `aria-valuemax={100}` `aria-label="Upload progress"`
- `animated-circular-progress-bar`: `aria-label="Validation conditions met: N of 3"` — programmatic label
- Pulsating ring (urgency): purely visual — no ARIA. The button itself has clear label. Screen readers don't need to know about the urgency ring.
- Evidence list: `aria-live="polite"` on the evidence list container — new items announced as they appear
